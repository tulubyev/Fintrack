# Многоуровневая система администрирования FinTrack

## Обзор
FinTrack реализует продвинутую многоуровневую систему администрирования с шестью различными ролями, каждая из которых имеет специализированные права доступа и функции. Система обеспечивает гранулярный контроль доступа и разделение обязанностей между различными административными функциями.

## Административные роли

### 1. Супер Администратор (super_admin)
**Описание:** Наивысший уровень доступа с полным контролем над системой.

**Права доступа:**
- Полный доступ ко всем функциям системы
- Управление пользователями и их ролями
- Системные настройки и конфигурация
- Доступ ко всем административным панелям других ролей

**Ключевые функции:**
- Назначение и изменение ролей других администраторов
- Управление системными параметрами
- Критические операции безопасности
- Окончательные решения по системным изменениям

### 2. DevOps Администратор (devops_admin)
**Описание:** Специализируется на технической инфраструктуре и производительности системы.

**Права доступа:**
- `system.monitoring` - Мониторинг системы
- `system.performance` - Анализ производительности
- `system.resources` - Управление ресурсами
- `system.updates` - Системные обновления
- `system.maintenance` - Техническое обслуживание
- `logs.system` - Системные логи
- `metrics.performance` - Метрики производительности

**Ключевые функции:**
- Мониторинг работы серверов и сервисов
- Анализ производительности приложения
- Управление обновлениями системы
- Диагностика технических проблем

### 3. Аналитический Администратор (analytics_admin)
**Описание:** Отвечает за бизнес-аналитику, отчеты и метрики пользователей.

**Права доступа:**
- `analytics.view` - Просмотр аналитики
- `analytics.export` - Экспорт аналитических данных
- `reports.generate` - Генерация отчетов
- `metrics.view` - Просмотр метрик
- `dashboard.analytics` - Аналитический дашборд
- `users.analytics` - Аналитика пользователей
- `transactions.analytics` - Аналитика транзакций

**Ключевые функции:**
- Создание бизнес-отчетов
- Анализ пользовательского поведения
- Метрики использования системы
- Экспорт данных для внешнего анализа

### 4. Финансовый Администратор (finance_admin)
**Описание:** Управляет финансовыми операциями, транзакциями и банковскими интеграциями.

**Права доступа:**
- `transactions.view` - Просмотр транзакций
- `transactions.manage` - Управление транзакциями
- `banks.manage` - Управление банковскими подключениями
- `payments.view` - Просмотр платежей
- `financial.reports` - Финансовые отчеты
- `compliance.view` - Соответствие требованиям

**Ключевые функции:**
- Мониторинг финансовых операций
- Управление банковскими интеграциями
- Финансовая отчетность
- Контроль соответствия нормативным требованиям

### 5. API Администратор (api_admin)
**Описание:** Отвечает за внешние интеграции, API и сторонние сервисы.

**Права доступа:**
- `api.monitoring` - Мониторинг API
- `api.management` - Управление API
- `integrations.view` - Просмотр интеграций
- `webhooks.manage` - Управление вебхуками
- `api.alerts` - Уведомления API
- `third_party.status` - Статус сторонних сервисов

**Ключевые функции:**
- Мониторинг внешних API
- Управление интеграциями с банками
- Настройка вебхуков
- Контроль работы сторонних сервисов

### 6. Администратор Безопасности (security_admin)
**Описание:** Специализируется на безопасности системы, аутентификации и мониторинге угроз.

**Права доступа:**
- `security.monitoring` - Мониторинг безопасности
- `auth.logs` - Логи аутентификации
- `security.alerts` - Уведомления безопасности
- `ip.analysis` - Анализ IP-адресов
- `threats.analysis` - Анализ угроз
- `access.control` - Контроль доступа
- `audit.logs` - Журналы аудита

**Ключевые функции:**
- Мониторинг попыток взлома
- Анализ подозрительной активности
- Управление правами доступа
- Аудит системы безопасности

## Техническая реализация

### Middleware аутентификации
```typescript
// server/middleware/adminAuth.ts
export const requireAdmin = (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
  if (!req.user?.adminRole) {
    return res.status(403).json({ error: 'Access denied. Admin role required.' });
  }
  next();
};

export const requirePermission = (permission: Permission) => {
  return (req: AuthenticatedRequest, res: Response, next: NextFunction) => {
    const userRole = req.user.adminRole;
    const permissions = ADMIN_PERMISSIONS[userRole] || [];
    
    if (!permissions.includes('*') && !permissions.includes(permission)) {
      return res.status(403).json({ error: 'Insufficient permissions.' });
    }
    next();
  };
};
```

```typescript
// shared/schema.ts
export const users = pgTable("users", {
  // ... другие поля

  // ...
});
```

### Frontend интерфейс
Админ-панель динамически показывает доступные функции на основе роли пользователя:
- Роль отображается цветной меткой
- Показываются только разрешенные действия
- Интуитивно понятная навигация по функциям

## Безопасность

### Принципы безопасности
1. **Принцип наименьших привилегий** - каждая роль имеет только необходимые права
2. **Разделение обязанностей** - критические операции требуют участия нескольких ролей
3. **Аудит действий** - все административные действия логируются
4. **Временные ограничения** - возможность установки временных прав доступа

### Логирование и аудит
Все административные действия автоматически записываются с указанием:
- Времени выполнения
- Пользователя и его роли
- Выполненного действия
- Результата операции

## Расширение системы

### Добавление новых ролей
1. Обновить константы `ADMIN_PERMISSIONS` в `adminAuth.ts`
2. Добавить описание роли в админ-панель
3. Обновить документацию
4. Провести тестирование прав доступа

### Добавление новых прав
1. Определить новое право в типе `Permission`
2. Назначить право соответствующим ролям
3. Реализовать проверки в API endpoints
4. Обновить интерфейс админ-панели

## Лучшие практики

### Для разработчиков
- Всегда используйте middleware `requirePermission` для защиты endpoints
- Проверяйте права доступа на frontend для улучшения UX
- Логируйте все административные операции
- Регулярно проводите аудит прав доступа

### Для администраторов
- Назначайте минимально необходимые права
- Регулярно пересматривайте назначенные роли
- Мониторьте активность администраторов
- Используйте временные повышения привилегий для разовых задач

## Мониторинг и метрики
