# E1.0 — Платформа этапа 1

**Оценка:** 8 дней · **Зависит от:** этап 0 · **Блокирует:** все эпики этапа 1

## Цель и ценность
Дать остальным эпикам общие механизмы, без которых каждый будет изобретать своё:
- версионируемые миграции БД вместо `drizzle-kit push`;
- фоновые задачи для разбора выписок, LLM, детекторов и уведомлений;
- журнал продуктовых событий для метрик активации и D30;
- in-app уведомления;
- каркас SPA с маршрутами вместо одного «единого дашборда» в `App.tsx`.

Пользователь видит только последний пункт: у приложения появляется навигация, адресуемые экраны и центр уведомлений.

## Что есть в коде сейчас
- `lib/db/package.json`: скрипты `push` и `push-force`. Миграций нет. `docs/DEPLOY.md` описывает сверку схемы через `drizzle-kit push --strict` под `fintrack_user` с ответом «No».
- Фоновых задач нет. Redis нет. `services/tokenCache.ts` — кеш в памяти процесса.
- Продуктовой аналитики нет. `middleware/metrics/*` собирает технические метрики HTTP.
- `App.tsx` (460 строк): `UnifiedDashboard` на inline-стилях, секции раскрываются кнопками, роутинга нет. При этом `wouter` уже в зависимостях, а `components/layout/Sidebar.tsx` (с `Link` из wouter и пунктами `/`, `/accounts`, `/cards`, `/analytics`, `/goals`, `/investments`, `/ai`, `/settings`, `/testing`) и `components/layout/Header.tsx` написаны, но **нигде не подключены**.
- `hooks/useAuth.ts` существует, но `App.tsx` ведёт авторизацию сам через `localStorage` и `fetch`.

- [ ] Есть скрипт `pnpm --filter @workspace/db run migrate`, который применяет миграции через `drizzle-orm/node-postgres/migrator`. Повторный запуск ничего не меняет.
- [ ] На проде базовая миграция помечена применённой без выполнения SQL; процедура описана в `docs/DEPLOY.md`.
- [ ] CI падает, если схема в `schema/index.ts` изменена без миграции (шаг `drizzle-kit check` плюс проверка, что `generate` даёт пустой diff).
- [ ] Скрипты `push` и `push-force` удалены из `lib/db/package.json`.
- [ ] Фоновые задачи: задача, поставленная в очередь, выполняется воркером не позже чем через 5 с. Упавшая задача повторяется 3 раза с экспоненциальной паузой. После перезапуска контейнера задачи не теряются.
- [ ] Воркер работает отдельным контейнером `fintrack-worker` (тот же образ, `WORKER_MODE=only`) без `ports:`, в сети `traefik-public`. В api-контейнере `WORKER_MODE=off`.
- [ ] `POST /api/v1/events` принимает пачку до 50 событий. Событие не из списка отбрасывается, ответ `202`. Свойства, похожие на ПДн (e-mail, телефон, 16 цифр подряд), вырезаются валидатором и логируются как warning.
- [ ] Серверный `track()` пишет события в той же транзакции БД, что и бизнес-действие, или после неё; падение записи события не роняет запрос.
- [ ] `GET /api/v1/notifications` возвращает список с курсором; в шапке показывается число непрочитанных; клик помечает уведомление прочитанным и ведёт на `deepLink`.
- [ ] Маршруты `/`, `/transactions`, `/accounts`, `/accounts/:id`, `/import`, `/budgets`, `/goals`, `/subscriptions`, `/categories`, `/settings`, `/admin/*` открываются по прямой ссылке и после F5 (nginx уже отдаёт `index.html` на любой путь).
- [ ] При ширине < 768 px вместо боковой панели показывается нижняя навигация из 5 пунктов: Главная, Операции, «+», Бюджеты, Ещё.
- [ ] `UnifiedDashboard` и захардкоженный список операций удалены из `App.tsx`. Состояние авторизации живёт в `useAuth`.
- [ ] Удаление пользователя (`deleteUserData`) удаляет все его строки во всех таблицах: интеграционный тест создаёт данные во всех пользовательских таблицах и проверяет, что после удаления ничего не осталось.

## Модель данных

### Миграции (без изменения таблиц)
- `lib/db/drizzle.config.ts`: добавить `out: "./migrations"`, `migrations: { table: "__drizzle_migrations", schema: "drizzle" }`.
- `lib/db/src/migrate.ts`: вызывает `migrate(db, { migrationsFolder })`. Скрипт `"migrate": "tsx src/migrate.ts"`.
- Базовая миграция на проде: выполнить `CREATE SCHEMA drizzle`, создать таблицу журнала и вставить строку с хешем `0000_baseline` — точный SQL генерируется при подготовке и кладётся в `docs/DEPLOY.md`. Перед этим `pg_dump`, как в существующем runbook.

### Новые таблицы

```ts
// lib/db/src/schema/platform.ts (новый файл; index.ts реэкспортирует)
export const productEvents = pgTable("product_events", {
  id: bigserial("id", { mode: "number" }).primaryKey(),
  userId: uuid("user_id").references(() => users.id, { onDelete: "cascade" }),
  anonymousId: varchar("anonymous_id", { length: 64 }),
  sessionId: varchar("session_id", { length: 64 }),
  name: varchar("name", { length: 64 }).notNull(),
  props: jsonb("props").notNull().default({}),
  platform: varchar("platform", { length: 10 }).notNull(),    // web | pwa | android | ios | server
  appVersion: varchar("app_version", { length: 20 }),
  occurredAt: timestamp("occurred_at", { withTimezone: true }).notNull(),
  receivedAt: timestamp("received_at", { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  nameTimeIdx: index("product_events_name_time_idx").on(t.name, t.occurredAt),
  userTimeIdx: index("product_events_user_time_idx").on(t.userId, t.occurredAt),
}));
// Пока объём < 10 млн строк, секционирование не нужно. Хранение — 400 дней, чистит джоб cleanup.events.

export const notifications = pgTable("notifications", {
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  type: varchar("type", { length: 40 }).notNull(),  // budget_threshold | recurring_upcoming | recurring_new | import_done | goal_reached | system
  title: varchar("title", { length: 140 }).notNull(),
  body: text("body"),
  deepLink: varchar("deep_link", { length: 300 }),  // относительный путь SPA: /budgets?month=2026-10
  payload: jsonb("payload").notNull().default({}),
  dedupKey: varchar("dedup_key", { length: 120 }),  // budget:<id>:2026-10:80 — не создавать дубль
  readAt: timestamp("read_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({
  userCreatedIdx: index("notifications_user_created_idx").on(t.userId, t.createdAt),
  userDedupUq: uniqueIndex("notifications_user_dedup_uq").on(t.userId, t.dedupKey),
}));
```

Таблицы pg-boss (`pgboss.*`) библиотека создаёт сама в отдельной схеме при первом старте. Роли `fintrack_user` нужно право `CREATE` на базу или заранее созданная схема `pgboss` с владельцем `fintrack_user` — шаг добавляется в `docs/DEPLOY.md`.

### Каскадное удаление
Существующие FK на `users` объявлены без `onDelete`. Миграция `0002_user_cascade` пересоздаёт их с `ON DELETE CASCADE` для таблиц: `bank_connections`, `accounts`, `transactions`, `savings_goals`, `budgets`, `ai_chat_sessions`, `family_group_members`, `user_verifications`, `verification_codes`, `verification_requests`. `admin_logs.admin_user_id` и `system_settings.updated_by` — `SET NULL` (колонку `admin_user_id` сделать nullable). У `documents.user_id` нет FK, а тип `varchar` при `uuid` в `users.id`: файлы документов удаляются явно в `deleteUserData` вместе с записями. `deleteUserData` сводится к `DELETE FROM users WHERE id = $1` плюс удаление файлов из `/data`.

**Как сделано (T6, 27.10.2026):**
- Миграция `0025_user_cascade` снимает старые ключи по колонке, а не по имени: в базе, созданной до миграций, имя могло
  отличаться. Затем она ставит `ON DELETE CASCADE` для таблиц выше и для `family_groups.admin_user_id`, а также
  `document_verification_history.document_id → documents` и `family_group_members.group_id → family_groups`.
- `SET NULL` получили `admin_logs.admin_user_id` (колонка стала nullable), `system_settings.updated_by` и
  `verification_requests.reviewed_by`: удаление администратора не трогает чужие заявки.
- Удаление — `services/accountDeletion.ts`. В одной транзакции удаляются документы (`user_id` у них varchar, ключа нет) и
  пользователь. После фиксации стираются файлы: документы, каталог выписок `IMPORTS_DIR/<userId>` и фото профиля.
- Пользователь удаляет аккаунт сам через `DELETE /api/v1/me` с паролем: в вебе — «Настройки → Удаление аккаунта»,
  в приложении — «Удалить аккаунт» в настройках (этого требует и Google Play).
- `tests/accountDeletion.test.ts` берёт список таблиц со ссылкой на `users` из самой базы и требует, чтобы до удаления
  каждая была засеяна, а после — пуста.

## API

| Метод и путь | Тело / параметры | Ответ | Ошибки |
|---|---|---|---|
| `POST /v1/events` | `{ events: [{ name, props?, occurredAt, sessionId?, anonymousId?, platform, appVersion? }] }`, до 50 штук. Авторизация **необязательна**: до входа события идут с `anonymousId` | `202 { accepted: n }` | `400 VALIDATION_ERROR`, `429` (лимит 60 запросов в минуту на IP) |
| `GET /v1/notifications` | `?limit&cursor&unreadOnly=true` | `{ items: Notification[], nextCursor, unreadCount }` | — |
| `POST /v1/notifications/{id}/read` | — | `204` | `404` |
| `POST /v1/notifications/read-all` | — | `204` | — |

`Notification = { id, type, title, body, deepLink, payload, readAt, createdAt }`. При входе пользователя связь `anonymousId → userId` записывается событием `auth_logged_in`; переписывать старые строки не нужно.

## Экраны и состояния (каркас)

**Веб ≥ 768 px:** слева `Sidebar` (переписать пункты: Главная, Операции, Счета, Импорт, Бюджеты, Цели, Подписки, Категории; внизу Настройки и Админ-панель, если `adminRole` пришёл **с сервера**). **Мобильный < 768 px:** нижняя навигация (Главная, Операции, «+» — быстрое добавление из E1.1, Бюджеты, Ещё). «Ещё» открывает `Sheet` с остальными разделами. Колокольчик остаётся в шапке.

## Риски и открытые вопросы
- **Базовая миграция на проде.** Если схема прода разошлась с `schema/index.ts` (17.10.2026 в DEPLOY.md она совпадала), базовая миграция будет неверной. Перед пометкой — повторная сверка `push --strict` с ответом «No».
- **pg-boss создаёт схему** — нужны права. Альтернатива — создать схему заранее под `tulubyev` и выдать её `fintrack_user`.
- **Память воркера:** отдельный контейнер со своими 512 МБ; на VPS нужно проверить свободную память (`docs/Server_State.md` в `vps-server-infra`).
- **Аналитика своими силами** даёт меньше готовых отчётов, чем AppMetrica или PostHog, но не передаёт данные третьим лицам (D10).
- **Вопрос:** нужна ли e-mail-копия уведомлений в этапе 1? Предлагается только для `recurring_upcoming` и `budget_threshold` 100%, с отключением в настройках.
