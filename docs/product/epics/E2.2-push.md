# E2.2 — Push-уведомления (FCM, RuStore Push, APNs, Web Push)

**Оценка:** 8 дней · **Зависит от:** E2.1, E1.0 (таблица `notifications`, очереди), таблица устройств из этапа 0 · **Блокирует:** E2.7 (оперативные предупреждения), удержание D30

## Цель
Доставлять важное вовремя и только с согласия пользователя:
- списание подписки завтра;
- бюджет превышен;
- новая подписка;
- необычное списание (E2.7);
- «давно не загружали выписку».

Каждый тип можно отключить отдельно.

## Пользовательские истории
- Как пользователь, я хочу push за день до списания годовой подписки.
- Как пользователь, я хочу отключить напоминания о выписках, но оставить предупреждения о бюджете.
- Как пользователь телефона без сервисов Google (Huawei, часть Xiaomi), я тоже хочу получать уведомления.
- Как пользователь, я не хочу уведомлений ночью.

## Ключевые решения
- **Каналы и провайдеры:**
  - Android с Google Play Services — **FCM HTTP v1** (сервисный аккаунт Firebase; работу FCM для российских проектов и оплату Firebase **проверить** на момент старта);
  - Android без GMS и сборка `rustore` — **RuStore Push SDK** (для доставки нужен установленный RuStore или его push-сервис — **проверить** текущие требования; у RuStore есть «универсальные пуши», которые могут проксировать FCM и HMS — **проверить**);
  - iOS (E3.1) — **APNs** через `expo-notifications` (токен APNs, отправка напрямую через HTTP/2 с ключом `.p8`, не через Expo Push Service, чтобы не зависеть от сервиса в США — D13);
  - PWA (Android Chrome, iOS 16.4+ для установленных PWA) — **Web Push** с VAPID (`web-push`).
- В клиенте Expo: `expo-notifications` для FCM и APNs; для RuStore Push — нативный модуль через Expo Modules API или готовый пакет (**проверить** наличие поддерживаемого пакета); выбор провайдера по варианту сборки и наличию GMS.
- **Сервер:** очередь `push.send` (pg-boss).
  - Адаптеры `fcm`, `rustore`, `apns`, `webpush`.
  - Повторы при 5xx и таймаутах.
  - При ответах «токен недействителен» (FCM `UNREGISTERED`, APNs 410) устройство помечается `revoked`.
- Каждое in-app уведомление (`notifications`) создаётся как раньше. Затем по настройкам пользователя ставится задача отправки push. В payload — только `notificationId`, `type` и `deepLink`, текст короткий и без сумм, если включена «Скрывать суммы в уведомлениях».
- **Тихие часы** по `users.timezone`: по умолчанию 22:00–09:00, уведомления копятся и уходят в 09:00 (кроме `security_alert`).
- **Частота:** не больше 3 push в сутки на пользователя, кроме `security_alert`. Однотипные уведомления дня объединяются («3 напоминания о списаниях»).
- Тихие push «данные обновились» (data-only) после импорта на вебе — для синхронизации E2.1.

## Модель данных крупно
```ts
// devices (из этапа 0) — добавить:
pushProvider: varchar("push_provider", { length: 10 }),   // fcm | rustore | apns | webpush
pushToken: text("push_token"),                            // для webpush — JSON подписки (endpoint, keys), шифруется
pushTokenUpdatedAt: timestamp("push_token_updated_at", { withTimezone: true }),
pushRevokedAt: timestamp("push_revoked_at", { withTimezone: true }),
// уникальный индекс (push_provider, push_token)

export const notificationPrefs = pgTable("notification_prefs", {
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  type: varchar("type", { length: 40 }).notNull(),   // budget_threshold | recurring_upcoming | recurring_new | security_alert | import_reminder | goal_reached | product_news
  push: boolean("push").notNull().default(true),
  email: boolean("email").notNull().default(false),
  inApp: boolean("in_app").notNull().default(true),
}, (t) => ({ pk: primaryKey({ columns: [t.userId, t.type] }) }));
// users: quiet_hours_start smallint default 22, quiet_hours_end smallint default 9, hide_amounts_in_push boolean default false

export const pushDeliveries = pgTable("push_deliveries", {       // журнал на 30 дней
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  notificationId: uuid("notification_id").references(() => notifications.id, { onDelete: "cascade" }),
  deviceId: uuid("device_id").notNull(),
  provider: varchar("provider", { length: 10 }).notNull(),
  status: varchar("status", { length: 12 }).notNull(),   // sent | failed | invalid_token | deferred
  providerMessageId: varchar("provider_message_id", { length: 200 }),
  error: text("error"),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});
```

## API крупно
- `PUT /v1/devices/current/push` `{ provider, token }` → `204`.
- `DELETE /v1/devices/current/push` → `204`.
- `GET /v1/notification-prefs` и `PUT /v1/notification-prefs` (список типов с каналами, тихие часы, «скрывать суммы»).
- `POST /v1/notifications/test` — тестовый push на текущее устройство, не чаще раза в минуту.
- `GET /v1/push/vapid-public-key` — без авторизации.

## Экраны
Настройки → Уведомления: таблица «Тип × канал (Push / E-mail / В приложении)», тихие часы, «Скрывать суммы», кнопка «Проверить уведомления».

Запрос разрешения (Android 13+ `POST_NOTIFICATIONS`, iOS) — не при первом запуске, а после первой ценности: например, после импорта — «Напомнить о списании подписок за день?».

## Метрика
Доставка (sent / attempted) ≥ 95%. Открываемость (`notification_clicked` / `notification_shown`) ≥ 8%. Доля пользователей, отключивших push полностью, < 15% за месяц.

## Риски и вопросы
- **Доступность FCM в РФ** и оплата Firebase-проекта; запасной путь — RuStore Push для всех Android.
- **Huawei без GMS и без RuStore** — HMS Push Kit не планируется (**решить** по доле аудитории после запуска).
- **Тексты** не должны раскрывать финансовые данные на заблокированном экране — опция «Скрывать суммы» по умолчанию **включена** для `security_alert`.

## Как сделано

- **T1 (#182):**
  - **Устройство — это сессия входа** (`auth_sessions`), отдельной таблицы `devices` нет. Токен лежит в `push_provider`,
    `push_token` и `push_token_updated_at`. Шифрование детерминированное (`fieldEncryption`, назначение `push-token`),
    поэтому токен уникален. Если на том же телефоне вошёл другой пользователь, токен переезжает к его сессии.
    Любой отзыв сессии стирает токен (`revokedSessionFields`).
  - **Группы уведомлений** (`services/notificationPrefs.ts`, `PREF_GROUPS`) — вместо типов из спецификации. Группа объединяет
    несколько типов `notifications`: например, «Новые подписки и списания после отмены» — это `recurring_new` и `recurring_after_cancel`.
  - **Каналы — push и письмо.** Канал «в приложении» не отключается: колокольчик — это история, по ней уходят push и письма.
  - **По умолчанию:** push включён, письма — у групп, где они есть по D19. «Новости FinTrack» выключены везде: реклама только
    с согласия, 38-ФЗ.
  - **Тип без группы (`system`):** push не уходит, письмо решает тот, кто создаёт уведомление.
  - **Письма** проверяют и общий переключатель D19, и настройку группы.
  - **API:** `PUT`/`DELETE /api/v1/devices/current/push`, `GET`/`PUT /api/v1/notification-prefs`. Тихие часы и
    `users.hide_push_amounts` сохраняются уже сейчас, применяются при отправке (T2).

- **T2 (#183):**
  - **Цепочка:** `notify()` ставит задачу `push.send` с singletonKey «пользователь + тип». Задача (`services/push/pushService.ts`):
    - проверяет группу в настройках;
    - в тихие часы откладывает себя до их конца, кроме группы безопасности;
    - забирает все необработанные уведомления этого типа за сутки — так однотипные объединяются в один push
      («2 уведомления: скорое списание подписки»);
    - соблюдает лимит: не больше 3 push в сутки, кроме безопасности;
    - шлёт на каждое устройство.
  - **Отметка `notifications.push_processed_at`**: повтор не уходит. Уведомления, созданные до выкатки, миграция помечает
    обработанными.
  - **Повторы — внутри задачи, по каждому устройству** (2 повтора, 1 и 4 с); сама задача не повторяется, иначе push ушёл бы
    второй раз на устройства, уже получившие первый. Недействительный токен (FCM `UNREGISTERED`/404, Web Push 404/410)
    снимается с устройства.
  - **Адаптеры:** FCM HTTP v1 — OAuth-токен сервисного аккаунта подписываем сами (JWT RS256), без google-auth-library.
    Web Push — пакет `web-push`.
  - **«Скрывать суммы»** заменяет суммы с валютой на «•••» в заголовке и тексте; для безопасности — всегда.
  - **Журнал `push_deliveries`:** 30 дней, чистит `cleanup.notifications`.
  - **Ключ VAPID:** `GET /api/v1/push/vapid-public-key`.
  - **Не сделано:** тихий push «данные обновились» после импорта — вместе с регистрацией push в приложении (T4).
