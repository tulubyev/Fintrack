# E1.7 — PWA

**Оценка:** 4,5 дня · **Зависит от:** E1.0 (маршруты, нижняя навигация), E1.2 (мастер импорта — для Share Target) · **Блокирует:** ничего; страховка на случай проблем со сторами (E2.9, E3.1)

## Цель и ценность
FinTrack ставится на телефон как приложение с сайта fin-wall.ru: иконка на экране, полноэкранный режим, быстрый запуск, просмотр последних данных без сети. На Android выписку из банковского приложения можно отправить в FinTrack через «Поделиться». До выхода в сторы это единственная «мобильная» версия. После выхода — запасной путь, если приложение удалят из App Store или Google Play.

## Что есть в коде сейчас
- `artifacts/fintrack/index.html`:
  - `lang="en"`;
  - `maximum-scale=1` (мешает масштабированию, это проблема доступности);
  - подключено ~25 семейств Google Fonts одним запросом — сотни КБ блокирующего CSS и шрифтов, внешняя зависимость.
- `public/` содержит только `favicon.svg` и `robots.txt`. Манифеста, иконок и service worker нет.
- `deploy/nginx.conf`: `/assets/` кешируется на год (immutable), остальное — `no-cache` с fallback на `index.html`. Для `sw.js` и `manifest.webmanifest` отдельных правил нет: они попадут в `location /` и получат `no-cache` — это правильно. MIME для `.webmanifest` нужно проверить: по умолчанию nginx может отдать `application/octet-stream`.
- Vite 7 (`catalog:`), React 18, TanStack Query 5.

## Пользовательские истории
1. Как пользователь Android, я хочу установить FinTrack на главный экран из браузера и открывать его как приложение.
2. Как пользователь iPhone, я хочу понятную инструкцию «Поделиться → На экран „Домой“».
3. Как пользователь, я хочу без сети видеть последние загруженные баланс и операции с пометкой «нет сети, данные от 14:32».
4. Как пользователь Android, я хочу в приложении банка нажать «Поделиться» на PDF-выписке, выбрать FinTrack и сразу попасть в мастер импорта.
5. Как пользователь, я хочу, чтобы после обновления сайта приложение подхватило новую версию без переустановки.

## Критерии приёмки
- [ ] Lighthouse (мобильный профиль) на `/` для вошедшего пользователя: PWA installable, Performance ≥ 80, Accessibility ≥ 90.
- [ ] `manifest.webmanifest`:
  - `name: "FinTrack — личные финансы"`, `short_name: "FinTrack"`, `lang: "ru"`;
  - `start_url: "/?source=pwa"`, `scope: "/"`, `display: "standalone"`;
  - `theme_color` и `background_color` из токенов темы;
  - иконки 192, 512 и maskable 512 (PNG) и `apple-touch-icon` 180;
  - `shortcuts`: «Добавить операцию» → `/?action=add`, «Загрузить выписку» → `/import`.
- [ ] Service worker (Workbox через `vite-plugin-pwa`, стратегия `generateSW`) предкеширует только оболочку: `index.html`, хешированные `/assets/*`, иконки. **API-ответы в кеш SW не попадают** (`navigateFallbackDenylist: [/^\/api\//]`, без runtimeCaching для `/api`).
- [ ] Офлайн: последние данные главной, операций (первая страница) и счетов показываются из кеша TanStack Query, сохранённого в IndexedDB (`@tanstack/query-async-storage-persister` + `idb-keyval`), с баннером «Нет сети. Данные от 17.10, 14:32». Запись операций офлайн недоступна: кнопка «+» показывает «Нужна сеть» (офлайн-очередь — в E2.1).
- [ ] При выходе из аккаунта кеш IndexedDB и кеш запросов очищаются полностью. Тест: после выхода и перезагрузки без сети данные не видны.
- [ ] Persist-кеш хранится не дольше 7 дней (`maxAge`) и только для ключей из белого списка (`dashboard`, `transactions-first-page`, `accounts`, `categories`).
- [ ] Обновление: при новой версии SW показывается тост «Доступна новая версия — Обновить» (`registerType: 'prompt'`); по клику — `skipWaiting` и перезагрузка.
- [ ] Android Chrome и Яндекс Браузер: собственная кнопка «Установить приложение» через `beforeinstallprompt` в меню «Ещё» и на главной после 2-го визита; скрывается после установки или отказа (повтор через 30 дней).
- [ ] iOS Safari: баннер с инструкцией (иконка «Поделиться» → «На экран „Домой“»), показывается раз в 30 дней, только в Safari и не в standalone.
- [ ] Share Target (Android, установленное PWA): в манифесте `share_target` с `method: "POST"`, `enctype: "multipart/form-data"`, `files: [{ name: "file", accept: ["application/pdf", "text/csv", ".csv", "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet", ".xlsx", "application/vnd.ms-excel", ".xls"] }]`, `action: "/import/share"`. SW перехватывает POST, кладёт файлы в IndexedDB и редиректит на `/import?shared=1`; мастер забирает файлы и начинает загрузку. Если пользователь не вошёл — сначала вход, затем продолжение.
- [ ] `index.html`: `lang="ru"`, `maximum-scale=1` убран, шрифты — одно семейство (Inter или основной шрифт темы, проверить в `tailwind.config.ts`), самостоятельно хостится через `@fontsource`; Google Fonts удалены.
- [ ] Ключевые экраны (главная, операции, быстрое добавление, импорт, бюджеты, подписки) проверены на 360×640 и 390×844: нет горизонтальной прокрутки, цели нажатия ≥ 44 px, safe-area (`env(safe-area-inset-bottom)`) у нижней навигации.
- [ ] nginx: `types { application/manifest+json webmanifest; }`. `sw.js` и `manifest.webmanifest` — `Cache-Control: no-cache`. `Service-Worker-Allowed` не нужен (SW в корне).

## Модель данных
Не меняется. На клиенте — IndexedDB `fintrack` с хранилищами `query-cache` (persist TanStack Query) и `shared-files` (временные файлы Share Target, удаляются после загрузки или через 1 час).

## API
Новых эндпоинтов нет. Share Target использует `POST /v1/imports` из E1.2. События установки — через `POST /v1/events` (E1.0).

## Экраны и состояния
| Экран / элемент | Состояния |
|---|---|
| Кнопка «Установить приложение» (Ещё → Установить; карточка на главной) | Доступно (`beforeinstallprompt`), Установлено (скрыта), iOS (инструкция), Не поддерживается (скрыта) |
| Баннер «Нет сети» | Сверху над контентом; есть кеш: «Данные от …»; кеша нет: «Нет сети. Подключитесь к интернету, чтобы увидеть данные» |
| Тост «Новая версия» | Показывается один раз до перезагрузки |
| `/import?shared=1` | Файл получен → загрузка (E1.2, шаг 2); файл не поддерживается → ошибка `UNSUPPORTED_FILE`; не вошёл → вход, затем возврат |
| Splash (standalone) | Цвет фона и иконка из манифеста; на iOS — `apple-touch-startup-image` не делаем (много размеров), фон из `background_color` |

## Риски и открытые вопросы
- **Финансовые данные в IndexedDB** на общем устройстве. Белый список ключей, срок 7 дней, очистка при выходе; шифрование не делаем, так как ключ всё равно лежал бы рядом в браузере. В E2.1 у мобильного приложения хранилище будет защищённым.
- **iOS:** нет `beforeinstallprompt` и Share Target. Web Push для установленных PWA на iOS 16.4+ возможен — он пойдёт в E2.2 вместе с остальными push.
- **Яндекс Браузер и Samsung Internet:** поведение установки и Share Target **проверить** на устройствах. Российская аудитория Android часто пользуется ими.
- **Вопрос:** выделять ли офлайн-запись операций в этап 1? Предлагается нет: это требует очереди, идемпотентности и разрешения конфликтов, которые полноценно делаются в E2.1 и затем переносятся в PWA.
