# E2.1 — Мобильное приложение на Expo (Android, затем iOS)

**Оценка:** 28 дней · **Зависит от:** этап 0 (refresh-токены, сессии и устройства, OpenAPI v1), эпики E1.* (API) · **Блокирует:** E2.2, E2.3, E2.9, E3.1

## Цель
Нативное приложение, которое делает всё, что веб этапа 1: главная, операции, быстрое добавление, импорт через «Поделиться», бюджеты, цели, подписки. Плюс то, чего веб не умеет: вход по PIN и биометрии, офлайн-просмотр и офлайн-запись с синхронизацией, а в перспективе — push и чтение уведомлений банков.

## Пользовательские истории
- Как пользователь, я хочу входить по PIN или отпечатку, а не вводить пароль каждый раз.
- Как пользователь, я хочу записать трату в метро без сети, чтобы она синхронизировалась потом.
- Как пользователь, я хочу поделиться PDF-выпиской из банковского приложения прямо в FinTrack.
- Как пользователь, я хочу, чтобы приложение блокировалось при сворачивании дольше чем на 5 минут.
- Как пользователь, я хочу видеть данные мгновенно при запуске (из локальной базы), а свежие — через секунду.

## Ключевые решения

**Монорепо и сборка**
- Пакет `artifacts/mobile` (`@workspace/mobile`, T1): Expo SDK 58, React Native 0.88, React 19.3, `expo-router`. Закреплённые в каталоге `react: 19.1.0` и `react-dom: 19.1.0` (след шаблона Replit) убраны — версии React задаёт сам пакет.
- Веб (`artifacts/fintrack`) остаётся на React 18. SDK 58 работает с изолированными зависимостями pnpm без `node-linker=hoisted`: Metro смотрит в `node_modules` пакета и корня (`metro.config.js`). Пиры Radix внутри `expo-router` (`react-dom`, `@types/react-dom`) объявлены в самом пакете, иначе pnpm подставляет версии 18 из веба.
- `minimumReleaseAge: 1440` в `pnpm-workspace.yaml` действует и на Expo-пакеты — учитывать при обновлениях SDK.
- Сборка (D13, решено 23.10.2026): `expo prebuild` + Gradle в GitHub Actions (`.github/workflows/mobile-android.yml`), APK — в артефактах; без секретов подписи — отладочный ключ. Обновления JS: собственный endpoint `expo-updates` (позже; политики сторов разрешают OTA для JS без смены функциональности — **проверить** для RuStore).
- Варианты сборки (`app.config.ts` + `EXPO_PUBLIC_FLAVOR`): `rustore`, `play`, `apk` (с E2.3 — разные разрешения), позже `ios`.

**Навигация** (`expo-router`, T6)
- **Вкладки** — `src/app/(tabs)`: Главная · Операции · ＋ · Бюджеты · Ещё.
  - «＋» — не вкладка: нажатие открывает модальный быстрый ввод `/quick-add`.
- **«Ещё»:**
  - Счета, Цели, Подписки, Категории, Правила категорий, Импорт, Настройки, Синхронизация;

- **Стек-экраны:** операция, счёт, бюджет, подписка (серия), импорт, выбор категории.
  - Заголовок и «назад» задаёт корневой `_layout.tsx` (`STACK_SCREENS`).
  - Выбор категории с любого экрана — `await pickCategory(kind)` (`lib/picker.ts`).
- **Пути повторяют сайт:** `/transactions`, `/accounts/:id`, `/budgets/:id`, `/goals`, `/subscriptions`, `/categories`, `/categories/rules`, `/import`, `/settings`.
  - `deepLink` уведомлений (путь SPA) открывает тот же экран в приложении.
  - Только у приложения: `/transactions/:id`, `/more`, `/quick-add`, `/category-picker`, `/sync-issues`.
  - Разбор маршрутов проверяет тест `tests/routes.test.ts`.
- **Ссылки** (`lib/links.ts`, `+native-intent.tsx`):
  - `fintrack://<путь>`;
  - `https://fin-wall.ru/app/<путь>` — Android App Links (`intentFilters` с `autoVerify`); Universal Links на iOS — `associatedDomains` при сборке с `APPLE_TEAM_ID`;
  - ссылка с чужого домена открывает главную.
- **Файлы привязки домена** собирает web-контейнер при старте (`deploy/40-app-links.sh`) из `ANDROID_CERT_SHA256` и `APPLE_APP_ID` в `.env`.
  - Отладочный ключ не публикуется: им может подписаться любое приложение.
  - Пусто — файлы отдают 404, и ссылки открывают сайт.
  - Без приложения nginx переадресует `/app/<путь>` → `/<путь>` (относительный `Location`, чтобы за Traefik не уйти на `:8080`).
  - Порядок выкатки — в `docs/DEPLOY.md` («Ссылки в приложение»).
- **UI-кит** (`src/ui/theme.ts`, `src/ui/kit.tsx`) — свои компоненты на `StyleSheet` и токенах темы (цвета из темы веба, светлая и тёмная).
  - Компоненты: `Page` (отступы, крупный заголовок, pull-to-refresh → синхронизация), `Card`, `Section`, `ListItem`, `Money`, `Badge`, `Chip`, `EmptyState`, `Sheet` (нижний лист), `Button` (primary / secondary / danger / link).
  - Иконки — Ionicons (`@expo/vector-icons`), отклик при записи — `expo-haptics`.
  - nativewind и Tamagui не взяли: лишняя сборочная прослойка над Metro в монорепо ради десятка компонентов.

**API-клиент** (T2, `lib/shared`)
- Генерировать из `lib/api-spec/openapi.yaml` пока не из чего: там описан только `/healthz`, а веб ходит в API v1 через ручные модули `features/*/api.ts`. Общий код вынесен руками в `@workspace/shared`:
  - `money` — суммы строками и копейки в `bigint` (D11);
  - `api` — `ApiRequestError`, `withQuery`, `errorMessage` и `createApiClient`.
- `createApiClient`:
  - access-токен — в заголовке; при `401` выполняется одно обновление `POST /api/auth/refresh` с refresh-токеном в теле, затем повтор запроса;
  - параллельные запросы ждут то же обновление;
  - на холодном старте, когда access-токена нет, сессия обновляется до запроса;
  - `401` на обновлении чистит сессию и вызывает `onSessionExpired`, сбой сети или `503` её не трогает.
- Типы сущностей переезжают из `features/*/api.ts` в `lib/shared` вместе с экранами приложения (T7, T8). Хуки TanStack Query остаются у каждого клиента свои.
- **Риск:** сервер меняет refresh-токен при каждом обновлении и хранит только хеш нового. Если ответ на обновление потерялся в сети, новый токен пропал, и пользователю придётся войти заново: повтор старого в течение 60 с даёт `401`, позже — отзыв сессии. Для мобильной сети это заметно; решать в T3 вместе со входом по PIN, например окном, в котором повтор старого токена возвращает ту же новую пару.

**Токены и вход** (T3)
- Refresh-токен — в `expo-secure-store`:
  - на Android — Keystore, в резервную копию не попадает (`configureAndroidBackup`);
  - на iOS — Keychain, `WHEN_UNLOCKED_THIS_DEVICE_ONLY`.

  Access-токен — только в памяти.
- Вход — по телефону или e-mail и паролю, как в вебе; при включённой 2FA — второй шаг с кодом. SMS-входа в API нет: SMS используется только для сброса пароля. Регистрация и восстановление пароля — на сайте.
- После входа — PIN из 4–6 цифр, хеш scrypt с солью (`@noble/hashes`, N=2¹²) в SecureStore. Биометрия (`expo-local-authentication`) включается только после успешной проверки и открывает тот же вход.
- **Биометрия только по разрешению (D20):** по умолчанию выключена. Включается `MOBILE_BIOMETRICS_ENABLED` или супер-администратором. Приложение спрашивает `GET /api/v1/app-config`, хранит последний ответ, а при запрете отключает уже включённую биометрию.
- 5 неверных PIN подряд стирают токены и PIN, сессия завершается на сервере, нужен полный вход. Счётчик переживает перезапуск.
- Блокировка: при холодном старте и после ухода в фон дольше 5 минут. Экран блокировки закрывает приложение целиком, не сбрасывая открытый экран.
- Ядро — `src/auth/controller.ts` без зависимостей от React Native, покрыто тестами (`pnpm --filter @workspace/mobile run test`).
- **Устройство:** таблицы `devices` из этапа 0 нет. Сессия называется по `User-Agent` приложения — «FinTrack/0.1.0 (Android 15; Pixel 8)»; так и видно в списке сессий. Таблица устройств с push-токенами — в E2.2.
- **Сервер (T3):** заменённый refresh-токен в течение 60 с получает ту же новую пару, а не 401. Это закрывает потерянный в мобильной сети ответ на обновление. Новая пара хранится зашифрованной ключом из старого токена (`auth_sessions.replay_token_enc`); позже повтор, как и раньше, отзывает сессию.
- Заглушка в списке недавних приложений (`FLAG_SECURE`) — «по настройке»; появится с экраном настроек в T10.

**Локальное хранение и офлайн** (T5, `artifacts/mobile/src/data`)
- **База** — `expo-sqlite` с SQLCipher (`useSQLCipher` в config-плагине).
  - Ключ — 256 случайных бит в SecureStore, задаётся сырым `PRAGMA key`.
  - Удалённое затирается на диске (`secure_delete`).
  - В Expo Go SQLCipher нет, там база без шифрования — только для разработки. Сборка без SQLCipher данные не хранит.
- **Схема** — одна таблица `records(entity, id, data, server, …)` вместо зеркала каждой таблицы, плюс `outbox` и `kv`. Версия — `PRAGMA user_version`.
  - `data` — то, что видит экран; `server` — последняя версия с сервера.
  - Колонки `account_id`, `category_id`, `date` — для ленты и фильтров.
  - Почему не drizzle и не таблица на сущность: записи хранятся в формах DTO сервера (`toTransactionDto` и т. п.), и новое поле на сервере не требует миграции на телефоне.
- **Ядро без React Native** — `store.ts` (хранилище и очередь) и `sync.ts` (синхронизация).
  - Тесты — на настоящем SQLite (`node:sqlite`), `pnpm --filter @workspace/mobile run test`.
  - Привязка к устройству — `device.ts`, хуки для экранов — `hooks.ts` (`useLocal`, `useSyncState`).
- **Чтение:** экран читает из SQLite через `useLocal(() => store.list(...))`. Данные перечитываются после любой правки и синхронизации, TanStack Query для них не нужен.
- **Запись** — `store.mutate`, для операций готовы `createTransaction`, `updateTransaction`, `deleteTransaction`.
  - Правка сразу видна и встаёт в `outbox` с клиентским `id` (UUID v7).
  - Неотправленные правки одной записи сливаются в один запрос; создание и удаление до отправки не отправляют ничего.
  - Отправка строго по порядку: операция в новый счёт не уйдёт раньше счёта.
  - Нет ответа (сеть) — повтор при появлении сети или возврате в приложение. `5xx`, `408`, `429` — повтор с паузой от 5 с до 15 мин. `401` — правка ждёт.
  - Другой `4xx` — правка отклонена, локальная запись возвращается к серверной, ошибка ждёт решения «повторить / отменить». `DELETE` → `404` считается успехом.
- **Синхронизация** — раунд «забрать → отправить → забрать».
  - Сначала забираем, чтобы правку без сети сравнить со свежей серверной версией.
  - Страница и её курсор применяются одной транзакцией. `410 CURSOR_EXPIRED` → стираются серверные записи без неотправленных правок, затем полный снимок.
  - Когда: вход и разблокировка, возврат в приложение, появление сети (`expo-network`), раз в 15 минут, пока приложение открыто, и «Синхронизировать» на главной.
  - **Фоновая синхронизация перенесена в E2.2**, вместе с push «данные обновились»: на Android фоновые задачи ненадёжны (Doze), а для фона нужен вход без экрана.
- **Конфликты** — на уровне полей, а не записи.
  - Синхронизация принесла серверную версию, где поля из неотправленной правки изменили иначе → правка ждёт решения «оставить мою / взять с сервера» (экран `sync-issues`). До решения видна своя правка.
  - Правки разных полей сливаются сами.
  - `409 DUPLICATE_RESOURCE` при создании — тоже конфликт; «оставить мою» превращает создание в `PATCH`.
  - Удаление на сервере сильнее неотправленных правок.
  - Сервер остаётся источником истины для импортированных полей: правку суммы или даты импортированной операции он отклоняет (`409 OPERATION_NOT_ALLOWED`), и она откатывается.
- **Данные и сессия:**
  - явный выход и 5 неверных PIN стирают локальную базу;
  - истёкшая сессия сохраняет данные и неотправленные правки до входа того же пользователя;
  - вошёл другой пользователь — чужие данные стираются (`data/session.ts`).
- **Интерфейс:** плашка `SyncBanner` («Нет сети · изменения отправятся позже · 3 в очереди», «Нужно ваше решение…»). Временная главная (до T7) показывает данные с устройства и даёт записать трату без сети.

**Импорт на телефоне**
- Android: intent-filter на `application/pdf`, `text/csv`, `text/comma-separated-values`, `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`; приём файла через config-plugin share intent (`expo-share-intent` или аналог — **проверить** совместимость с SDK) → мастер импорта → `POST /v1/imports`.
- Выбор файла: `expo-document-picker`.
- **Как сделано (T9):**
  - **«Поделиться»** — `expo-share-intent@9` (версия для SDK 58, проверена `expo prebuild`): фильтр `SEND` с пятью типами выписок в манифесте, `singleTask`; iOS-расширение выключено (`disableIOS`). Модуль копирует присланный файл в кеш приложения. В Expo Go модуля нет — провайдер выключен.
  - `ShareIntentProvider` — в корневом `_layout`. После входа и разблокировки пришедшая выписка открывает `/import`, экран загружает её сам и сбрасывает share intent. Повторное «Поделиться» на том же экране тоже срабатывает.
  - **Выбор файла** — `expo-document-picker` с `*/*`: CSV на Android приходит с разными типами, а сервер всё равно проверяет файл по содержимому.
  - **Загрузка** — `FormData` с `{ uri, name, type }`: клиент API (`lib/shared/api`) отправляет `FormData` как multipart, без своего `Content-Type`.
  - **Мастер** — тот же серверный (`/api/v1/imports`, E1.2), экраны `import/index` и `import/[id]` повторяют путь сайта. Импорт — исключение из правила «экраны работают с локальной базой»: без сети он невозможен, а сохранённые операции приходят обычной синхронизацией (`sync.sync({ now: true })` после коммита и отмены).
  - **Шаги:** статус опрашивается раз в секунду. Для незнакомого формата на телефоне — подтвердить подсказку колонок одним нажатием, подробная настройка — ссылкой на сайт. Предпросмотр: счёт (свой или новый с названием из выписки), переключатель у каждой строки, «Импортировать N». Итог: «Загружено N за период», «Посмотреть траты», «Отменить импорт» с числом правленых операций.
  - На экране счёта — «Загрузить выписку» (`/import?accountId=`).
  - Категории строк на телефоне не правятся — их можно поменять после импорта в ленте.

**Наблюдаемость:** `@sentry/react-native` в GlitchTip или Sentry (D12), события продукта — в тот же `POST /v1/events` с `platform=android`.

## Новые серверные части
- `GET /api/v1/sync?cursor=<opaque>&limit=500` (T4, `services/syncService.ts`) → `{ changes: { accounts, categories, transactions, budgets, goals, goalContributions, recurring, rules }, deleted: { <сущность>: [id] }, nextCursor, hasMore }`.
  - Сущности приходят в тех же формах, что в REST v1: счета — с остатком в рублях, операции — `toTransactionDto`, правила — `toRuleDto`. Категории — системные и свои, с личными «скрыта» и названием. Бюджеты, цели, взносы и регулярные платежи — поля таблиц без устаревших колонок.
  - **Курсор — не по `updated_at`** (отличие от первоначального плана). Строка, записанная долгой транзакцией (импорт), получает время начала транзакции, а видна становится после коммита — клиент, уже прошедший это время, её бы потерял.
  - Вместо времени каждая строка хранит номер записавшей её транзакции (`sync_xid`, его ставит триггер `sync_touch`).
  - Раунд синхронизации запоминает xmin снимка — номер самой старой незавершённой транзакции. Следующий раунд берёт строки с `sync_xid >=` этого xmin.
  - Часть строк приходит повторно; клиент делает upsert по `id`.
  - Внутри раунда страницы идут по сущностям (счета и категории раньше операций), затем по `(sync_xid, id)`.
  - Первый раунд без курсора — полный снимок без удалённых. Следующие отдают удалённые (`deleted_at`) как надгробия.
  - Курсор раунда старше 90 дней → `410 CURSOR_EXPIRED`, клиент делает полный ресинк.
- Триггер `sync_touch` (миграция 0020) на 8 таблицах и `user_category_prefs`. Любой `UPDATE`, который меняет строку, записывает `sync_xid`, а если код не поставил `updated_at` сам — и его. Это покрывает массовые операции, пересчёты курсов и импорт. Запись без изменений ничего не трогает.
- Индексы `(user_id, sync_xid, id)` заменили неиспользуемые `(user_id, updated_at…)`. Жёстких удалений в этих таблицах нет — только вместе с пользователем.
- `POST /v1/auth/pin-unlock` **не нужен**: PIN проверяется локально и только открывает refresh-токен.

## Модель данных крупно
- Сервер: таблица `idempotency_keys` не нужна — идемпотентность обеспечивают клиентские `id`.
- Сервер (T4): во всех синхронизируемых таблицах есть `updated_at`, `deleted_at`, `sync_xid` и индекс `(user_id, sync_xid, id)`. Таблица устройств — в E2.2.
- Клиент (T5): `records` — зеркало синхронизируемых сущностей в формах DTO, `outbox` — очередь правок, `kv` — курсор, владелец данных, время синхронизации.

## Экраны
Повторяют веб этапа 1 с мобильными паттернами:
- свайпы в ленте операций;
- нижние листы вместо диалогов;
- крупная цифровая клавиатура в быстром вводе;
- pull-to-refresh, который запускает синхронизацию.

Состояния: офлайн (плашка «Нет сети · изменения отправятся позже · 3 в очереди»), ошибка синхронизации, конфликт («Операцию изменили на другом устройстве — оставить мою / взять с сервера»).

**Главная, лента, быстрый ввод (T7):**
- **Главная** считается из локальной базы той же логикой, что сводка сайта (`data/summary.ts` ↔ `services/dashboardService.ts`):
  - траты = −Σ `amountRub`; возврат в категорию расходов уменьшает траты;
  - переводы, корректировки и исключённые из статистики не считаются;
  - месяц сравнивается с тем же периодом прошлого;
  - топ — по родительским категориям; ближайшие списания — как `recurringApi.upcoming`.
- **Лента:**
  - `SectionList` по дням, страницы по 50;
  - поиск по колонке `records.search`: текст в нижнем регистре, ё = е — `lower()` в SQLite не знает кириллицу;
  - фильтры: период, тип, счёт, категория с подкатегориями, «без категории»;
  - итоги по фильтру — по `amount_kop`, сумма в рублях в копейках;
  - миграция локальной базы v2 добавляет эти колонки и дозаполняет старые строки при открытии;
  - параметры адреса (`?uncategorized=1`, `?period=month`, `?accountId=`) задают фильтр с главной и по ссылке.
- **Свайпы** (`ReanimatedSwipeable`): вправо — категория, влево — удалить с подтверждением.
- **Смена категории** — как на сайте: после выбора, если сервер видит похожие операции (`GET /transactions/:id/similar`), вопрос «только эта / эта и будущие / и прошлые». Без сети меняется только эта операция.
- **Правка:** сумма, тип, дата, счёт той же валюты — только у ручных расходов и доходов (сервер иначе отвечает `OPERATION_NOT_ALLOWED`); получатель, заметка, «не учитывать в статистике» — у всех. Уходят только изменённые поля.
- **Быстрый ввод:**
  - своя цифровая клавиатура (`lib/amountInput.ts`);
  - частые категории за 90 дней;
  - дата «сегодня / вчера / календарь» (`@react-native-community/datetimepicker`);
  - по умолчанию — счёт последней ручной операции.

**Счета, бюджеты, цели, подписки, категории (T8):**
- **Бюджеты** считаются на устройстве той же логикой, что `budgetService.listBudgets` (`data/budgets.ts`, тесты повторяют серверные случаи):
  - перенос остатка до 12 месяцев назад;
  - общий бюджет с исключёнными категориями, подкатегория внутри бюджета родителя;
  - статусы ok / warning / over, «ожидалось к сегодня», траты без бюджета.
  - Есть переключение месяцев, а в карточке — «можно N ₽ в день до конца месяца».
  - Правка и удаление — с текущего месяца, как на сайте: сервер заводит версии, они приходят синхронизацией.
  - Категории с действующим бюджетом в выборе не предлагаются.
- **Цели** считаются как в `goalService` (`data/goals.ts`):
  - накоплено = взносы или остаток привязанного счёта минус база;
  - прирост за 90 дней / 3, прогноз и нужный взнос.
  - «Уже отложено» при создании становится первым взносом. Снятие — отрицательный взнос.
  - Привязка к счёту — на сайте.
- **Счета:**
  - итог «в балансе», создание (вид, валюта, остаток), переименование, «учитывать в балансе», архив;
  - корректировка остатка через `POST /accounts/:id/balance-adjustments`: сервер заводит операцию-корректировку на разницу.
  - Остаток пересчитывает сервер. Операция, записанная без сети, попадёт в остаток после синхронизации.
- **Подписки:**
  - «нужно подтвердить» (`detected`) и подтверждённые;
  - стоимость в месяц (сумма × частота);
  - история списаний — операции с `recurringSeriesId`;
  - решения «подписка / не подписка / отменил».
- **Категории:**
  - переключатель «показывать в выборе» (скрытая остаётся у старых операций);
  - переименование: своя — `name`, системная — личное `customName`;
  - своя категория или подкатегория;
  - правила удаляются свайпом.
- **Очередь:** `409 DUPLICATE_RESOURCE` при создании значит «id занят» только у операций, счетов, целей и взносов. У бюджетов, категорий и правил тот же код — «такое уже есть», это отказ с текстом сервера, а не конфликт версий.

## Риски и вопросы
- **Санкционные риски EAS** (облако Expo в США, ключи подписи на их стороне) — D13. Запасной путь — локальная сборка в GitHub Actions на self-hosted раннере.
- **Перенос UI.** Веб-компоненты (shadcn/Radix и Tailwind) в React Native не переносятся. Общими будут API-клиент, zod-схемы, форматтеры (`utils/formatUtils.ts` — вынести в `lib/shared`), бизнес-расчёты (прогноз цели, темп бюджета — вынести в `lib/shared`). UI-кит для RN — **решить** (nativewind + собственные компоненты или Tamagui).
- **Фоновая синхронизация на Android** ограничена; основной триггер — открытие приложения и push.
