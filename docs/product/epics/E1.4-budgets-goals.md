# E1.4 — Бюджеты и цели

**Оценка:** 8 дней · **Зависит от:** E1.1, E1.3, E1.0 (джобы, уведомления) · **Блокирует:** блоки главного экрана E1.5, E3.2 (семейные бюджеты)

## Цель и ценность
Превратить «вижу траты» в «управляю тратами»:
- **лимиты по категориям** считаются из реальных операций и предупреждают заранее, а не в конце месяца;
- **копилки** показывают, когда цель будет достигнута при текущем темпе и сколько нужно откладывать, чтобы успеть к сроку.

## Что есть в коде сейчас
- Таблица `budgets(category varchar, monthly_limit, current_spent, month, year)`. `current_spent` **нигде не пересчитывается**. Бюджет заводится на каждый месяц отдельно.
- `routes/savings-budgets.ts`: `GET/POST /api/budgets`, `GET/POST/PATCH /api/savings-goals`. `PATCH /savings-goals/:goalId` не проверяет владельца (дыра этапа 0) и принимает любое тело.
- `savings_goals(current_amount)` — сумма вводится вручную, истории взносов нет.
- Фронтенд: `components/dashboard/SavingsGoals.tsx` (266 строк: список, прогресс, диалог создания на react-query) — написан, **не подключён**. UI бюджетов нет.

## Пользовательские истории
1. Как пользователь, я хочу задать лимит 25 000 ₽ в месяц на «Кафе и рестораны» один раз, а не каждый месяц.
2. Как пользователь, я хочу видеть, сколько потрачено и сколько осталось на сегодня, и получать предупреждение при 80% и при превышении.
3. Как новичок, я хочу, чтобы FinTrack предложил бюджеты по моим средним тратам за 3 месяца.
4. Как пользователь, я хочу общий лимит трат на месяц, кроме обязательных платежей.
5. Как пользователь, я хочу перенос остатка: недотратил 3 000 в октябре — в ноябре лимит 28 000.
6. Как пользователь, я хочу копилку «Отпуск» на 150 000 к 1 июня и видеть, сколько откладывать в месяц и успеваю ли я.
7. Как пользователь, я хочу привязать цель к накопительному счёту, чтобы прогресс считался сам по остатку.

## Расчёты
- **Исполнение бюджета** за период `[start, end)` (календарный месяц по `local_date` в часовом поясе пользователя):
  `spent = −Σ amount_rub` по операциям пользователя с `deleted_at IS NULL`, `status='posted'`, `exclude_from_stats=false`, `type IN ('expense','income')` и категорией из **поддерева** категории бюджета (родитель включает подкатегории). Возвраты (положительные суммы в категориях расходов) уменьшают `spent`. Переводы и корректировки не входят. Общий бюджет (`category_id IS NULL`) — по всем категориям `kind=expense`, кроме перечисленных в `excluded_category_ids`.
- **Темп:** `expected_by_today = limit × (прошло дней / дней в месяце)`. Статус: `ok` (spent ≤ expected), `warning` (spent > expected или ≥ 80% лимита), `over` (spent > limit).
- **Перенос остатка** (`rollover=true`): `limit_effective(m) = limit + max(0, limit_effective(m−1) − spent(m−1))`. Только положительный остаток и только с предыдущего месяца, без накопления за год — так проще объяснить в UI.
- **Предложение бюджета:** медиана трат категории за 3 полных прошлых месяца, округлённая вверх до 500 ₽. Предлагаются категории с медианой ≥ 1 000 ₽, не больше 8 штук.
- **Цель: текущая сумма.** При `account_id` — остаток счёта минус `account_baseline` (остаток на момент привязки, если выбрано «считать только новые деньги»); иначе `Σ goal_contributions.amount`.
- **Цель: прогноз даты.** Средний месячный прирост за 90 дней (`Δ/3`). Если он ≤ 0 — «при текущем темпе цель не будет достигнута». Иначе `дата = сегодня + ⌈(target − current) / прирост⌉ месяцев`.
- **Цель: нужный взнос:** `(target − current) / месяцев до target_date` (не меньше 1 месяца).

## Критерии приёмки
- [ ] Бюджет без `effective_to` действует во всех будущих месяцах; изменение лимита с текущего месяца закрывает старую версию (`effective_to` = последний день прошлого месяца) и создаёт новую — история прошлых месяцев не меняется.
- [ ] На один месяц нельзя создать два бюджета на одну категорию: `409`. Бюджет на родителя и на его подкатегорию одновременно разрешён; UI показывает подкатегорию внутри родителя.
- [ ] Тест расчёта: лимит 10 000, операции −3 000, −2 000 (подкатегория), +500 (возврат), перевод −4 000, операция с `exclude_from_stats` −1 000 → `spent = 4 500`.
- [ ] При пересечении 80% и 100% создаётся по одному in-app уведомлению на бюджет и месяц (`notifications.dedup_key = budget:<id>:<YYYY-MM>:<threshold>`). Повторный импорт дублей не создаёт.
- [ ] `budgets.check` выполняется не позже 2 минут после записи операций.
- [ ] Перенос остатка: при лимите 25 000 и тратах 22 000 в октябре лимит ноября = 28 000.
- [ ] «Предложить бюджеты» на пользователе с 3 месяцами данных возвращает от 1 до 8 предложений с суммами, равными медиане, округлённой вверх до 500.
- [ ] Цель с привязкой к счёту показывает остаток счёта; при отвязке сумма фиксируется взносом «Перенос остатка».
- [ ] Прогноз даты и нужный взнос считаются по формулам выше. Тест на трёх сценариях: растёт, стоит, падает.
- [ ] Пользователь B получает `404` на любые операции с бюджетами и целями пользователя A (в том числе на `PATCH` цели — регрессия дыры этапа 0).
- [ ] Старые записи `budgets` смигрированы. Колонка `current_spent` больше не читается и удалена в конце этапа.

## Модель данных

### `budgets` v2
```ts
export const budgets = pgTable("budgets", {
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  categoryId: uuid("category_id").references(() => categories.id, { onDelete: "cascade" }), // null — общий бюджет
  amount: decimal("amount", { precision: 15, scale: 2 }).notNull(),   // было monthly_limit
  period: varchar("period", { length: 10 }).notNull().default("month"),
  effectiveFrom: date("effective_from").notNull(),                     // 1-е число месяца
  effectiveTo: date("effective_to"),                                   // null — бессрочно
  rollover: boolean("rollover").notNull().default(false),
  excludedCategoryIds: uuid("excluded_category_ids").array().notNull().default(sql`'{}'`), // для общего бюджета
  alertThresholds: integer("alert_thresholds").array().notNull().default(sql`'{80,100}'`),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).notNull().defaultNow(),
  deletedAt: timestamp("deleted_at", { withTimezone: true }),
  // удаляются после миграции: category, monthly_limit, current_spent, month, year, is_active
}, (t) => ({
  userPeriodIdx: index("budgets_user_period_idx").on(t.userId, t.effectiveFrom, t.effectiveTo),
  userUpdatedIdx: index("budgets_user_updated_idx").on(t.userId, t.updatedAt),
}));
```
Пересечение версий для одной категории запрещено **exclusion-ограничением** или проверкой в сервисе в транзакции с `SELECT … FOR UPDATE`. Exclusion по `daterange` требует `btree_gist`; если расширение недоступно — проверка в сервисе.

**Миграция:** для каждой старой строки `effective_from = make_date(year, month, 1)`, `effective_to = (effective_from + interval '1 month' - interval '1 day')::date`, `amount = monthly_limit`, `category_id` по словарю E1.3-T3. Строки с `is_active=false` → `deleted_at = now()`.

## API

**BudgetStatus** = `{ id, categoryId, category: { name, icon, color }, amount, effectiveAmount (с переносом), spent, remaining, percent, expectedByToday, status: 'ok'|'warning'|'over', rollover, effectiveFrom, effectiveTo, children?: BudgetStatus[] }`

| Метод и путь | Запрос | Ответ | Ошибки |
|---|---|---|---|
| `GET /v1/budgets` | `?month=YYYY-MM` (по умолчанию текущий) | `{ month, items: BudgetStatus[], total: { amount, spent, remaining }, unbudgetedSpent }` | `400` |
| `POST /v1/budgets` | `{ id?, categoryId \| null, amount, rollover?, fromMonth?='текущий', excludedCategoryIds?, alertThresholds? }` | `201 BudgetStatus` | `409` (на категорию уже есть бюджет в этом периоде), `404` (чужая категория) |
| `PATCH /v1/budgets/{id}` | `{ amount?, rollover?, alertThresholds?, excludedCategoryIds?, fromMonth? }`; изменение `amount` с `fromMonth` > `effective_from` создаёт новую версию | `BudgetStatus` | `404` |
| `DELETE /v1/budgets/{id}` | `?fromMonth=YYYY-MM`: закрыть с этого месяца (по умолчанию текущий) | `204` | `404` |
| `GET /v1/budgets/suggestions` | — | `[{ categoryId, median3m, suggestedAmount }]` | — |
| `POST /v1/budgets/bulk` | `{ items: [{ categoryId, amount }] }` (принять предложения) | `{ created: BudgetStatus[] }` | `409` с перечнем конфликтов |
| `GET /v1/goals` | `?includeArchived=false` | `{ items: Goal[] }` | — |
| `POST /v1/goals` | `{ id?, name, targetAmount, targetDate?, accountId?, countOnlyNewMoney?, initialAmount?, icon?, color?, description? }` | `201 Goal` | `400`, `404` |
| `PATCH /v1/goals/{id}` | `{ name?, targetAmount?, targetDate?, accountId? \| null, icon?, color?, description? }` | `Goal` | `404` |
| `POST /v1/goals/{id}/archive` | — | `Goal` | `404` |
| `DELETE /v1/goals/{id}` | — | `204` | `404` |
| `GET /v1/goals/{id}/contributions` | `?limit&cursor` | `{ items, nextCursor }` | `404` |
| `POST /v1/goals/{id}/contributions` | `{ id?, amount, date?, note?, transactionId? }` | `201 { contribution, goal: Goal }` | `409`, если цель привязана к счёту (тогда взносы не вводятся вручную) |
| `DELETE /v1/goals/{id}/contributions/{cid}` | — | `204` | `404` |

**Goal** = `{ id, name, description, targetAmount, currentAmount, percent, targetDate, accountId, forecastDate | null, monthlyNeeded | null, avgMonthlyGrowth, onTrack: boolean | null, completedAt, archivedAt, icon, color }`

Старые `/api/budgets` и `/api/savings-goals` удаляются после перевода фронтенда.

## Экраны и состояния

### `/budgets`
- **Шапка:** переключатель месяца ‹ Октябрь 2026 ›, сводка «Потрачено 64 300 из 80 000 ₽ · осталось 15 700 ₽ на 14 дней (≈ 1 120 ₽/день)».
- **Норма:** карточки бюджетов, отсортированные по проценту. Прогресс-бар с отметкой «ожидаемо на сегодня», цвет по статусу. Подкатегории — внутри родителя. Внизу «Без бюджета: 12 400 ₽» и ссылка на операции.
- **Пусто, данных за 3 месяца нет:** «Бюджеты помогают не выходить за лимит. Задайте первый» и выбор категории.
- **Пусто, данные есть:** «Мы посмотрели ваши траты за 3 месяца и предлагаем бюджеты» — список предложений с галочками и полями сумм, «Создать выбранные».
- **Карточка бюджета:** график трат по дням против линии лимита (recharts), список операций месяца в категории, правка, «Перенос остатка», «Удалить с ноября».
- **Мобильный:** карточки во всю ширину; прогресс-бар 8 px; правка в `Sheet`.

### `/goals`

## Риски и открытые вопросы
- **Недели, кварталы и годы** не делаются в MVP (`period` заложен). Годовые расходы (страховка, отпуск) правильнее вести целями.
- **Бюджет на «Переводы людям»** спорен: часть переводов — на самом деле аренда или подарки. UI подсказывает переразметить через правила E1.3.
- **Вопрос:** e-mail при превышении бюджета или только in-app до появления push (E2.2)? Предлагается e-mail только для 100% с отключением в настройках.
