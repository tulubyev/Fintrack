# E1.2 — Импорт выписок

**Оценка:** 25,5 дня, из них срез P0 — 17 · **Зависит от:** E1.0 (очереди, воркер), E1.1 (счета, операции), E1.3-T1 · **Блокирует:** E1.6, E2.3 (дедупликация), E1.7-T4

## Цель и ценность
Главный способ получить реальные данные без открытых API банков. Пользователь скачивает выписку в своём банке и загружает её в FinTrack. Через 10 секунд он видит свои операции за 3–12 месяцев: с категориями, без дублей и с совпадающим остатком. Именно этот эпик определяет активацию: 30 операций в первые сутки — это одна выписка.

## Пользовательские истории
1. Как клиент Сбера, я хочу загрузить PDF-выписку по карте за полгода, чтобы сразу увидеть, куда уходят деньги.
2. Как клиент Т-Банка, я хочу загрузить CSV или XLSX из веб-версии, чтобы получить операции вместе с MCC и кешбэком.
3. Как пользователь, я хочу, чтобы повторная загрузка или выписка с пересекающимся периодом не создавали дублей.
4. Как пользователь, я хочу перед сохранением увидеть, сколько операций будет добавлено и сколько похоже на дубли, и решить спорные случаи сам.
5. Как пользователь, я хочу не помнить, как скачать выписку в моём банке: пусть FinTrack покажет короткую инструкцию.
6. Как пользователь банка, формат которого FinTrack не знает, я хочу один раз указать, где дата, сумма и описание, чтобы следующие файлы распознавались сами.
7. Как пользователь, я хочу отменить неудачный импорт целиком.
8. Как пользователь, я хочу загрузить несколько файлов разом (по разным картам).

Общие особенности, которые парсеры должны переносить:
- **Числа:** `1 234,56`; разделитель тысяч — обычный пробел, NBSP (U+00A0) или узкий NBSP (U+202F); минус — `-` или `−` (U+2212); суффиксы `₽`, `RUB`, `руб.`; знак `+` у пополнений.
- **Даты:** `дд.мм.гггг`, `дд.мм.гг`, `гггг-мм-дд`, с временем и без; в XLSX — серийные даты Excel.
- **Кодировка:** BOM, затем строгая проверка UTF-8 (`new TextDecoder('utf-8', { fatal: true })`), при ошибке — `windows-1251` (Node 24 собран с full-icu, отдельная библиотека не нужна).
- **Разделитель CSV:** считать `;`, `,` и `\t` в первых 5 строках вне кавычек.
- **Строки, которые не являются операциями:** итоги, «Остаток на…», пустые строки, повторяющиеся заголовки страниц.
- **Статусы:** отклонённые операции (`FAILED`, «Отклонена») не импортируются; блокировки (холды) — `status='pending'` (не входят в баланс и бюджеты, пока не появится проведённая).
- **Пароли и сканы:** PDF с паролем → ошибка `PDF_ENCRYPTED`; PDF без текстового слоя (скан) → `PDF_NO_TEXT` (OCR вне этапа 1).

## Архитектура

```
Браузер ──multipart──▶ POST /v1/imports ──▶ /data/imports/<user>/<id>.enc (AES-256-GCM)
                              │                 import_batches(status=uploaded)
                              └─ очередь import.parse ──▶ fintrack-worker
                                     detect() → parser.parse() → ParsedStatement
                                     сопоставление счёта → дедупликация → категоризация (предпросмотр)
                                     import_rows (staging) ; status=preview | needs_mapping | failed
Браузер ◀── опрос GET /v1/imports/:id (раз в 1 с) ──┘
Браузер ──▶ POST /v1/imports/:id/commit ──▶ очередь import.commit
                                     INSERT transactions (пачками по 500, одна транзакция БД)
                                     пересчёт баланса → status=done
                                     → categorize.llm, recurring.detect, budgets.check
```

- **Пакет `lib/statement-parsers`** (новый, чистые функции без БД):
  - `detect(file: { name, mime, bytes }, sample): Array<{ parserCode, score }>`;
  - `parse(bytes, opts): ParsedStatement`.
  - Каждый парсер имеет версию: `tbank_csv@1`, `sber_pdf@1`. Golden-тесты: фикстура → ожидаемый JSON.
- **PDF:** `pdfjs-dist` (legacy-сборка для Node). Берутся текстовые элементы с координатами `(x, y)`, строки собираются по `y` с допуском, колонки определяются по координатам заголовков. `pdf-parse` не подходит: теряет позиции и склеивает колонки.
- **XLSX/XLS:** SheetJS **из официального tarball** `cdn.sheetjs.com` (версия 0.20.3 или новее — **проверить** актуальную). Пакет `xlsx@0.18.5` из npm устарел и содержит известные уязвимости (prototype pollution CVE-2023-30533, ReDoS CVE-2024-22363). Защита от zip-бомб: проверять несжатый размер, не больше 50 МБ.
- **CSV:** `csv-parse/sync` после декодирования.
- **Изоляция:** разбор идёт в `worker_threads` внутри fintrack-worker с таймаутом 60 с и `resourceLimits.maxOldGenerationSizeMb = 256`. Не больше 300 страниц PDF и 50 000 строк.

```ts
type ParsedStatement = {
  parserCode: string; institution: string | null;
  accountCurrency: string | null; accountNumberMasked: string | null; cardLast4: string[];
  periodFrom: string | null; periodTo: string | null;        // YYYY-MM-DD
  openingBalance: string | null; closingBalance: string | null;
  rows: ParsedRow[]; warnings: string[];
};
type ParsedRow = {
  rowIndex: number; date: string; time: string | null; postedDate: string | null;
  amount: string;                // со знаком, в валюте счёта
  currency: string; originalAmount: string | null; originalCurrency: string | null;
  description: string; merchant: string | null; mcc: string | null; bankCategory: string | null;
  cardLast4: string | null; externalId: string | null; authCode: string | null;
  status: 'posted' | 'pending' | 'failed'; balanceAfter: string | null; cashback: string | null;
  raw: Record<string, string>;   // исходные ячейки — для отладки, хранятся только в import_rows
};
```

**Как сделан разбор (T1, разбор для T5 и T6)** — пакет `lib/statement-parsers`, только чистые функции, без БД:
- `parseStatement(file, { parserCode?, mapping?, mappings? })` → `parsed` (`ParsedStatement`) или `needs_mapping` (заголовок, первые 20 строк, отпечаток и предложенное сопоставление); ошибки — `StatementError` с кодом из списка ниже и текстом по-русски.
- Порядок выбора: явный `parserCode` → парсер банка с уверенностью ≥ 0,5 → сопоставление пользователя или запомненное по отпечатку заголовка (`mappings`: сервер передаёт сопоставления пользователя из `import_mappings`) → `needs_mapping`.
- Тип файла — по сигнатуре (`sniffFileType`): PDF и XLS пока дают ошибку с советом загрузить CSV или XLSX (PDF — T7).
- **XLSX читается своим кодом** (`src/xlsx.ts`, `src/zip.ts`), а не SheetJS. Выписке нужны только значения ячеек: общие и inline-строки, числа, даты по формату ячейки. Свой ридер не тянет зависимость, которую нельзя ставить из npm. Защита от zip-бомб — лимит 50 МБ несжатого и по заголовкам, и по факту распаковки.
- **CSV:** `csv-parse/sync`; кодировка — BOM → строгий UTF-8 → windows-1251; разделитель — по первым 5 строкам вне кавычек. Заголовок ищется после шапки выписки: первая строка с текстовыми ячейками, за которой в пределах пяти строк есть дата. Итоговые строки («Итого», «Остаток») пропускаются молча, прочие нечитаемые идут в `warnings`.
- **Т-Банк** — `tbank_csv@1` и `tbank_xlsx@1` по одному набору колонок. Берётся «Сумма платежа» в валюте карты; при другой валюте покупки «Сумма операции» уходит в `originalAmount`. Статус `FAILED` → `failed`, сервер такие строки не импортирует. `WAITING` → `pending`.
- **Универсальный** — `generic_csv@1` и `generic_xlsx@1`. Сопоставление ссылается на колонки по тексту заголовка; `suggestMapping` узнаёт дату, описание, сумму или пару «приход / расход», валюту, MCC, категорию и формат даты.
- **Ключ дедупликации** — `normalizeDescription`, `dedupHash`, `dedupSequence` по правилам ниже; хеш считает сервер при разборе (T13).
- **Golden-тесты** (`tests/golden`): синтетическая фикстура → эталонный JSON. Обновить эталон: `UPDATE_GOLDEN=1 pnpm --filter @workspace/statement-parsers test`, затем просмотреть дифф. XLSX в тестах собирается из ячеек (`tests/helpers/xlsx.ts`), бинарных фикстур в git нет.
- Фикстуры построены по описанию форматов из таблицы выше. Сверка с реальными выписками (T2) ещё впереди: при расхождении парсер получает новую версию (`@2`), старая остаётся для повторного разбора.

**Как сделаны загрузка и разбор (T3, T4)** — `artifacts/api-server/src/services/imports`, маршруты `routes/v1/imports.ts`:
- Таблицы — как в «Модели данных» ниже, плюс `import_batches.parse_result` (jsonb): предупреждения, карты, номер счёта и валюта из выписки, а при `needs_mapping` — превью таблицы и предложенное сопоставление. Индекс `tx_dedup_uq` и FK `transactions.import_batch_id` добавлены той же миграцией (0022).
- `POST /api/v1/imports` → `202`. Тип файла определяется по сигнатуре: картинка, архив и старый XLS → `415 UNSUPPORTED_FILE` с советом. Больше 15 МБ → `413 FILE_TOO_LARGE`. Чужой или некорректный `accountId` → `404`. 30 загрузок в сутки на пользователя считаются по `import_batches` → `429 RATE_LIMITED`. Повторный файл (тот же sha256 у неотменённого импорта) → `duplicateOfImportId`.
- Файл: `IMPORTS_DIR/<userId>/<batchId>.enc` (в образе `/data/imports`; каталог создаётся сам — существующий том папок из образа не получает). AES-256-GCM, ключ — HKDF от `ENCRYPTION_KEY` с меткой `fintrack:imports`. Формат: `FTI1 | iv | tag | шифртекст`.
- **Разбор** — задача `import.parse` в воркере (`services/imports/parse.ts`). Сопоставления пользователя из `import_mappings` передаются в `parseStatement`. Итог пишется одной транзакцией и только пока батч в статусе `parsing`: повтор задачи безопасен, а импорт, удалённый во время разбора, не воскреснет. Отклонённые банком строки сразу получают `skipped` и решение `skip`. Ошибка разбора → `failed` с кодом и текстом из `StatementError`, непредвиденная — `INTERNAL`.
- CSV и XLSX разбираются прямо в задаче; изоляция в `worker_threads` с таймаутом и лимитом памяти добавится вместе с PDF (T7).
- `GET /api/v1/imports` (новые сверху, курсор), `GET /:id` (опрос статуса), `GET /:id/rows` (с предпросмотра, фильтр `status`, курсор по `rowIndex`, без исходных ячеек), `DELETE /:id` до коммита: стирает файл и строки, статус `cancelled`.
- **Очистка** — `cleanup.imports` в 04:45 МСК (D8): файл удаляется через 30 дней после загрузки, строки — через 30 дней после коммита. Неоконченный импорт старше 30 дней переходит в `cancelled` без строк.
- События `import_started`, `import_parsed`, `import_mapping_required`, `import_failed` пишет сервер; остальные имена из таблицы аналитики уже в `EVENT_NAMES`.

**Как сделаны сопоставление, дубли, коммит и отмена (T5, T13 — срез P0, T14)** — `services/imports/prepare.ts`, `commit.ts`:
- `PUT /:id/mapping` `{ mapping, remember }` — из `needs_mapping`, `preview` или `failed` с `BAD_MAPPING`. Колонки сверяются с заголовком файла (`parse_result.table` или превью); файл разбирается заново. «Запомнить» записывается в `import_mappings` только после успешного разбора (флаг в данных задачи `import.parse`).
- **После разбора:**
  - подбор счёта: выбранный при загрузке (с предупреждением, если цифры карты не совпали) → единственный счёт с теми же последними 4 цифрами и банком → предложение создать «Банк •• 1234» (`parse_result.suggestedAccount`);
  - если счёт известен — строгая дедупликация;
  - для каждой строки — предложение категории конвейером E1.3: `suggested_category_id` и `categorization` в `import_rows`.
- **Строгий ключ** — по правилам выше. Если в счёте уже k операций с хешем, строки файла с seq ≤ k — дубли (`match_transaction_id` указывает на найденную операцию). Новые получают `dedup_seq` = максимум в счёте + 1, 2…, поэтому мягко удалённые операции не мешают индексу. Строка в другой валюте, чем счёт, — `error`. Нечёткие кандидаты, слияние с ручными и холды (T13, P1) — позже.
- **Решения:** `import_rows.decision = null` — по статусу (новая → импорт, остальное → пропуск); не null — выбор пользователя. `PATCH /:id/rows` меняет решение и категорию (`import_rows.category_id`); пропущенную банком или ошибочную строку импортировать нельзя, `merge` — только для `possible_duplicate`.
- **`POST /:id/commit`** `{ accountId }` или `{ createAccount }` → `202 committing`:
  - проверки: архивный счёт → `409 ACCOUNT_ARCHIVED`, валюта выписки ≠ валюте счёта → `409 CURRENCY_MISMATCH`;
  - новый счёт создаётся сразу, `source = 'import'`.
- **Задача `import.commit`** — одной транзакцией:
  - дубли проверяются заново против текущего счёта;
  - операции вставляются пачками по 500 (`source = 'import'`, `import_batch_id`, ключ дедупликации);
  - холды — `status = 'pending'`; категории предпросмотра переиспользуются, если счёт тот же, иначе считаются заново;
  - первый импорт в пустой счёт берёт остаток на начало из выписки; при остатке на конец считается сверка (`balanceCheck`);
  - остаток счёта пересчитывается.
- Ошибка коммита откатывает всё: батч возвращается в `preview` с `INTERNAL` или `COMMIT_REJECTED` и текстом. После коммита ставятся нейросеть для нераспознанных категорий, `recurring.detect` и `budgets.check`.
- **`POST /:id/undo`** (до 30 дней после коммита) мягко удаляет операции батча, пересчитывает остаток, батч → `undone`. Перед отменой `GET /:id` показывает `editedCount` — операции со своей категорией или заметкой. После отмены тот же файл снова загружается без пометки «уже загружали».

## Дедупликация

1. **Повторный файл.** Если пользователь уже загружал файл с таким же `sha256` и импорт не отменён, в ответе загрузки будет `duplicateOfImportId`, а на экране — «Этот файл уже загружали 12.10.2026». Продолжить можно, все строки окажутся дублями.
2. **Строгий ключ** — для пересекающихся периодов одного формата.
   - `norm(description)`: нижний регистр; `ё → е`; удалить последовательности из 6 и более цифр (референсы, коды авторизации), маски карт (`*1234`, `•• 1234`), даты и время внутри текста; схлопнуть пробелы; первые 100 символов.
   - `dedup_hash = sha256(account_id | local_date | amount в копейках | currency | norm(description))`.
   - `dedup_seq` — номер вхождения одинакового хеша внутри файла по порядку строк (1, 2, 3…). Две одинаковые покупки кофе за 250 ₽ в один день получают seq 1 и 2.
   - Уникальный индекс `tx_dedup_uq (account_id, dedup_hash, dedup_seq) WHERE deleted_at IS NULL AND dedup_hash IS NOT NULL`.
   - Если в БД уже есть k операций с этим хешем, то строки файла с seq ≤ k — дубли, с seq > k — новые.
   - Если банк даёт `externalId`, используется уникальность `(account_id, external_transaction_id)`.
3. **Нечёткие кандидаты** — для разных форматов одного банка (PDF и CSV), для ручных операций и (в этапе 2) для операций из уведомлений. Кандидат — операция в том же счёте с той же суммой (для валютных — ±3% по `amount_rub`), разницей дат ≤ 2 дней и без строгого совпадения, у которой выполнено одно из условий:
   - сходство описаний по триграммам ≥ 0,4 (считается в JS на небольшом наборе кандидатов, расширение `pg_trgm` не нужно);
   - источник существующей операции — `manual` или `notification`.

   Такая строка помечается `possible_duplicate`. Решение по умолчанию: для `manual` и `notification` — **объединить** (импортированная операция становится основной, категория, заметка и `recurring_series_id`, заданные пользователем, переносятся, ручная мягко удаляется); для импорта против импорта — **пропустить**. Пользователь может изменить решение в предпросмотре.
4. **Холды.** `pending` из прошлого импорта плюс `posted` с той же суммой ±1 день → `pending` заменяется.

**Сверка остатка.** Если в выписке есть остаток на конец, а у счёта нет других источников, при первом импорте `opening_balance` и `opening_balance_date` берутся из выписки (остаток на начало и `periodFrom`). При последующих импортах расчётный остаток на `periodTo` сравнивается с выпиской. При расхождении больше 1 ₽ показывается предупреждение и кнопка «Добавить корректировку» (через E1.1).

**Сопоставление счёта.** По `cardLast4` или последним 4 цифрам номера счёта ищутся `accounts.last_four` пользователя с тем же `institution_code`. Одно совпадение — предлагается этот счёт. Ни одного — предлагается создать счёт (банк, валюта, 4 цифры из выписки). Если загрузка начата со страницы счёта, используется он, а при несовпадении цифр показывается предупреждение.

## Критерии приёмки
- [ ] Для каждого парсера P0 есть ≥ 2 синтетических фикстуры. Golden-тест: число строк, суммы, даты, описания и остатки совпадают с эталоном до копейки.
- [ ] Сумма импортированных операций за период равна разнице остатков в шапке выписки (Сбер PDF, Альфа, ВТБ — где остатки есть). Тест на фикстурах.
- [ ] Повторная загрузка того же файла: 0 новых, все строки — дубли, показано предупреждение о повторном файле.
- [ ] Два файла с пересечением периодов в 10 дней создают объединение без дублей. Две одинаковые покупки в один день импортируются обе.
- [ ] Ручная операция «Кофе 250 ₽ вчера» и та же операция в выписке → в предпросмотре одна строка `possible_duplicate` с действием «объединить»; после коммита в счёте одна операция с категорией, заданной вручную.
- [ ] Строки со статусом `FAILED` (Т-Банк) не импортируются и в предпросмотре отмечены «Пропущено: отклонена банком».
- [ ] Неизвестный CSV → статус `needs_mapping` и экран сопоставления. После сопоставления второй файл с тем же заголовком распознаётся автоматически.
- [ ] PDF с паролем → `PDF_ENCRYPTED` с понятным текстом. Скан → `PDF_NO_TEXT`. Файл больше 15 МБ → `413`. Неподдерживаемый тип (по сигнатуре, не по расширению) → `415 UNSUPPORTED_FILE`.
- [ ] Выписка на 1 000 операций: от окончания загрузки до предпросмотра не больше 10 с p90. PDF на 200 страниц разбирается не дольше 60 с, пик памяти воркера — не больше 300 МБ.
- [ ] Коммит атомарен: при ошибке в середине не остаётся ни одной операции батча. Баланс счёта пересчитан.
- [ ] Отмена импорта (`undo`) в течение 30 дней мягко удаляет все операции батча, пересчитывает баланс и пишет событие. Если операции были отредактированы, пользователь видит их число до подтверждения.
- [ ] Исходный файл хранится в `/data/imports` зашифрованным (AES-256-GCM, ключ из `ENCRYPTION_KEY` через HKDF с меткой `imports`) и удаляется джобом через 30 дней (D8). Строки `import_rows` удаляются через 30 дней после коммита.
- [ ] Пользователь B не может читать, коммитить и отменять импорт пользователя A (`404`).
- [ ] Лимит частоты: 30 загрузок в сутки на пользователя (`429`).
- [ ] Все тексты ошибок по-русски, каждая с действием: «Скачайте выписку заново» или «Загрузите CSV вместо PDF».

## Модель данных

```ts
export const importBatches = pgTable("import_batches", {
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  accountId: uuid("account_id").references(() => accounts.id, { onDelete: "set null" }),
  fileName: varchar("file_name", { length: 255 }).notNull(),
  fileSize: integer("file_size").notNull(),
  fileSha256: varchar("file_sha256", { length: 64 }).notNull(),
  fileType: varchar("file_type", { length: 10 }).notNull(),         // csv | xlsx | xls | pdf
  storedPath: varchar("stored_path", { length: 300 }),              // null после очистки
  parserCode: varchar("parser_code", { length: 40 }),               // tbank_csv@1 | sber_pdf@1 | generic_csv@1
  institutionCode: varchar("institution_code", { length: 30 }),
  status: varchar("status", { length: 16 }).notNull().default("uploaded"),
    // uploaded | parsing | needs_mapping | preview | committing | done | failed | cancelled | undone
  errorCode: varchar("error_code", { length: 40 }),
  errorMessage: text("error_message"),
  columnMapping: jsonb("column_mapping"),
  periodFrom: date("period_from"), periodTo: date("period_to"),
  statementOpeningBalance: decimal("statement_opening_balance", { precision: 15, scale: 2 }),
  statementClosingBalance: decimal("statement_closing_balance", { precision: 15, scale: 2 }),
  stats: jsonb("stats").notNull().default({}),   // { total, new, duplicate, possibleDuplicate, skipped, error, imported }
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  parsedAt: timestamp("parsed_at", { withTimezone: true }),
  committedAt: timestamp("committed_at", { withTimezone: true }),
  undoneAt: timestamp("undone_at", { withTimezone: true }),
}, (t) => ({
  userCreatedIdx: index("import_batches_user_created_idx").on(t.userId, t.createdAt),
  userShaIdx: index("import_batches_user_sha_idx").on(t.userId, t.fileSha256),
}));

export const importRows = pgTable("import_rows", {
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  batchId: uuid("batch_id").notNull().references(() => importBatches.id, { onDelete: "cascade" }),
  rowIndex: integer("row_index").notNull(),
  parsed: jsonb("parsed").notNull(),          // ParsedRow без raw
  raw: jsonb("raw"),                          // исходные ячейки; удаляются вместе со строкой
  status: varchar("status", { length: 20 }).notNull(),   // new | duplicate | possible_duplicate | skipped | error
  decision: varchar("decision", { length: 10 }),           // import | skip | merge — выбор пользователя или значение по умолчанию
  matchTransactionId: uuid("match_transaction_id"),
  suggestedCategoryId: uuid("suggested_category_id"),
  errorMessage: text("error_message"),
  transactionId: uuid("transaction_id"),      // после коммита
}, (t) => ({ batchRowUq: uniqueIndex("import_rows_batch_row_uq").on(t.batchId, t.rowIndex),
            batchStatusIdx: index("import_rows_batch_status_idx").on(t.batchId, t.status) }));

export const importMappings = pgTable("import_mappings", {
  id: uuid("id").primaryKey().default(sql`gen_random_uuid()`),
  userId: uuid("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  headerFingerprint: varchar("header_fingerprint", { length: 64 }).notNull(), // sha256 нормализованной строки заголовка
  mapping: jsonb("mapping").notNull(),
    // { date: 'Дата операции', amount?: 'Сумма', income?: 'Приход', expense?: 'Расход', description: 'Описание',
    //   currency?, mcc?, category?, dateFormat: 'DD.MM.YYYY', decimal: ',', signConvention: 'signed'|'split'|'expense_positive',
    //   encoding, delimiter, skipRows }
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
}, (t) => ({ uq: uniqueIndex("import_mappings_user_fp_uq").on(t.userId, t.headerFingerprint) }));
```
Изменения `transactions`: FK `import_batch_id → import_batches.id ON DELETE SET NULL`, уникальный индекс `tx_dedup_uq` (см. выше). Колонки добавлены в E1.1.

## Экраны и состояния

Мастер `/import` (на мобильном — полноэкранные шаги, на десктопе — карточка 720 px):

1. **Выбор банка и загрузка.** Плитки банков: Сбер, Т-Банк, Альфа, ВТБ, Озон, Яндекс, «Другой банк». Под выбранной плиткой — инструкция «Как скачать выписку» (3–5 шагов, ссылка «Подробнее с картинками»; тексты и скриншоты **проверить** в каждом банке) и рекомендуемый формат («Для Т-Банка лучше CSV из веб-версии — в нём есть MCC»). Зона drag-and-drop и кнопка «Выбрать файлы» (можно несколько). Если пришли со страницы счёта, банк и счёт выбраны заранее.
2. **Разбор:** прогресс «Читаем выписку…» и имя файла. Несколько файлов — очередь со статусом каждого.
3. **Сопоставление** (только `needs_mapping`): таблица первых 20 строк, над каждой колонкой — выпадающий список «Дата / Сумма / Приход / Расход / Описание / Валюта / MCC / Категория банка / Не использовать», формат даты, «Расходы со знаком минус?». Живой предпросмотр трёх распознанных операций.
4. **Счёт:** «Операции по карте •• 1234. Добавить в счёт „Сбер Visa“?» или «Создать счёт „Сбер •• 1234“, RUB?».
5. **Предпросмотр:** чипы «245 новых · 12 уже есть · 3 похожи на дубли · 2 пропущены · 1 ошибка». Таблица с фильтром по статусу; у возможных дублей — пара строк «в FinTrack / в выписке» и переключатель «Объединить / Добавить / Пропустить». Колонка категорий с правкой. Предупреждение об остатке, если есть. Кнопка «Импортировать 245 операций».
6. **Готово:** «Загружено 245 операций за 01.07–30.09.2026». Кнопки «Посмотреть траты» (главная) и «Загрузить ещё выписку». Если E1.6 нашёл подписки — «Мы нашли 4 регулярных платежа на 7 890 ₽/мес».

Состояния ошибки — карточка с текстом по `errorCode` и действием. `FORMAT_NOT_RECOGNIZED` для PDF: «Мы пока не умеем читать этот PDF. Попробуйте CSV или Excel из веб-версии банка или отправьте нам пример (без загрузки: только название банка и тип выписки)» — форма обратной связи.

`/import/history` — список импортов: дата, банк, файл, период, число операций, статус, кнопка «Отменить» (30 дней).

## Риски и открытые вопросы
- **Форматы меняются.** Версии парсеров, мониторинг и ручное сопоставление как страховка. На поддержку закладывается 1–2 дня в месяц.
- **Образцы реальных выписок.** Нужны от команды и бета-пользователей с их согласия. Разбор — локально у разработчика, в репозиторий попадают только синтетические фикстуры. Процедуру обезличивания описать в `docs/import-formats.md`.
- **Сбер PDF без знака у списаний.** Знак определяется по `+` и по согласованности с колонкой остатка (`balanceAfter[i] = balanceAfter[i-1] + amount[i]` в хронологическом порядке). Это же проверяет корректность разбора.
- **Нагрузка на память** — отдельный воркер (E1.0, D9).
- **Хранение исходных файлов** — 30 дней или удалять сразу после коммита (D8). Это ПДн и банковская тайна клиента.
- **Мультивалютные счета в одной выписке** (Т-Банк, мультивалютная карта): строки с `Валюта платежа ≠ валюта счёта`. В MVP один батч = один счёт = одна валюта. Остальное → `CURRENCY_MISMATCH` с предложением разделить по валютам (P1).
- **Вопрос:** импорт Excel-таблиц Дзен-мани и CoinKeeper для переходящих пользователей? Хороший канал привлечения: свой парсер на 1–1,5 дня, P1 после основных банков.
