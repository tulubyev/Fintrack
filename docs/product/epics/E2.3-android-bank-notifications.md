# E2.3 — Чтение уведомлений банков на Android

**Оценка:** 14 дней · **Зависит от:** E2.1, E1.2 (дедупликация и слияние), E1.3 (категоризация) · **Блокирует:** —

## Цель
Операции появляются в FinTrack сами, через секунды после покупки, без выписок и без доступа к банку. Источник — push-уведомления банковских приложений (и SMS там, где это разрешено политикой стора). Разбор идёт **на устройстве**: текст уведомления не покидает телефон, на сервер уходят только распознанные поля.

Для пользователя это превращает FinTrack из «загружаю раз в месяц» в «вижу траты сразу». Ожидаемый эффект — заметный прирост D30.

## Пользовательские истории
- Как пользователь Android, я хочу один раз дать доступ к уведомлениям и видеть каждую покупку в FinTrack сразу.
- Как пользователь, я хочу выбрать, уведомления каких банков читать.
- Как пользователь, я хочу, чтобы при загрузке выписки эти операции не задвоились.
- Как пользователь, я хочу видеть, что не распознано, и помочь улучшить распознавание, не отправляя текст целиком.

## Ключевые решения
- **Android `NotificationListenerService`.**
  - Нативный модуль на Kotlin через Expo Modules API и config-plugin; требует development build, в Expo Go не работает.
  - Пользователь включает доступ в системных настройках («Доступ к уведомлениям»), приложение ведёт его туда экраном-инструкцией.
  - Обработка: фильтр по пакетам банков из белого списка → извлечение `title`, `text`, `bigText`, `postTime` → передача в JS через событие. Если JS не запущен — запись в локальную очередь (Room/SQLite) и обработка при запуске.
- **SMS** (`RECEIVE_SMS`) — только в вариантах `rustore` и `apk`. Google Play разрешает SMS-права лишь приложениям SMS по умолчанию и узким исключениям, поэтому в варианте `play` SMS выключены. Политики RuStore по SMS **проверить**.
- **Белый список пакетов** (**проверить** актуальные идентификаторы, в том числе APK-версии вне Google Play): Сбербанк Онлайн (`ru.sberbankmobile` и альтернативные сборки), Т-Банк (`com.idamob.tinkoff.android`), Альфа (`ru.alfabank.mobile.android`), ВТБ (`ru.vtb24.mobilebanking.android`), Озон Банк, Яндекс Банк / Яндекс Пэй, Газпромбанк, Райффайзен, Почта Банк. Список и шаблоны — в удалённой конфигурации.
- **Шаблоны разбора:**
  - версионированный JSON `bank-notification-templates.json`, раздаётся сервером `GET /v1/config/notification-templates` с подписью Ed25519 — приложение проверяет подпись, чтобы подмена конфигурации не позволила собирать лишнее;
  - на банк — набор регулярных выражений с именованными группами: `amount`, `currency`, `merchant`, `card_last4`, `balance`, `direction`, `kind` (`purchase`, `transfer_in`, `transfer_out`, `cash`, `refund`, `decline`, `otp`);
  - уведомления с `kind=otp` (коды подтверждения) и `decline` **отбрасываются сразу** и нигде не хранятся.
- **Что отправляется на сервер:** `POST /v1/transactions/ingest` с полями `{ clientId, institution, cardLast4, amount, currency, merchant, direction, postedAt, balanceAfter?, templateVersion }`. Текст уведомления не отправляется.
- **Сопоставление счёта:** по `institution` + `cardLast4` → `accounts.last_four`. Если счёта нет — предложить создать.
- **Дедупликация:**
  - `source='notification'`, `has_time=true`;
  - если тот же банк шлёт два уведомления на одну операцию (холд и проведение) — схлопнуть по `amount` + `merchant` + разница по времени < 10 минут;
  - при последующем импорте выписки работают нечёткие кандидаты E1.2: импортированная операция становится основной, категория и заметка пользователя переносятся.
- **Нераспознанные уведомления от банков из списка:**
  - хранятся только локально, 7 дней;
  - пользователь может нажать «Отправить пример»: текст маскируется (цифры → `#`, кроме структуры суммы) и уходит с явным согласием на `POST /v1/feedback/notification-sample`;
  - на сервере образцы доступны только админам для обновления шаблонов и удаляются через 30 дней.
- **Энергопотребление:** listener — системный сервис, фоновый процесс не нужен. Отправка — пачками при сети, через outbox E2.1.

## Модель данных крупно
- Сервер: новых таблиц почти нет.
  - `transactions.source='notification'`, `metadata.templateVersion`.
  - `notification_samples(id, userId, institution, maskedText, templateVersion, createdAt)` с удалением через 30 дней.
  - Справочник шаблонов — файл в репозитории, подписывается при сборке.
- Клиент: `notification_queue(id, package, postedAt, parsed json, status)` в SQLite.

## Экраны
- **Онбординг функции:**
  - что читаем;
  - что не читаем (коды, переписку);
  - что отправляем;
  - кнопка «Открыть настройки доступа».
  Это «prominent disclosure» по требованиям Google Play: текст и порядок экранов **проверить** по актуальной политике User Data.
- **Настройки → «Автоматический учёт»:** переключатели по банкам, статистика («за неделю распознано 42, не распознано 3»), «Отправить пример», «Отключить» (ведёт в системные настройки).
- **Лента операций:** бейдж источника «из уведомления», операции подтверждаются выпиской позднее.

## Метрика
Доля Android-пользователей, включивших функцию, ≥ 40%. Распознавание уведомлений банков из списка ≥ 90%. Доля задвоений после импорта < 1%. D30 включивших против невключивших — отслеживать.

## Риски и вопросы
- **Политика Google Play** может отклонить приложение с доступом к уведомлениям. Вариант `play` выходит с отдельной декларацией; при отказе функция остаётся только в `rustore` и `apk` (D14).
- **Банки меняют тексты** — шаблоны обновляются удалённо, без релиза, мониторинг доли нераспознанных.
- **На iOS невозможно.** Запасной путь для iOS — автоматизация «Быстрых команд» по SMS (iOS 17+) с отправкой на API — исследовать в E3.1.
- **Юридически:** пользователь передаёт свои данные сам. Согласие на обработку обновляется: пункт «данные из уведомлений банков». Объём — минимально необходимый.
