## D2. AI-провайдер и 152-ФЗ
**Вопрос.** Через какую модель обрабатывать данные пользователей: категоризация мерчантов (E1.3) и советник с инструментами (E2.4)? Сейчас все запросы уходят в OpenRouter (США) → `anthropic/claude-3.5-sonnet`.

| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Российская модель для всего** (GigaChat или YandexGPT) | Данные остаются в РФ, нет трансграничной передачи, проще согласие и уведомление РКН. | Качество function calling и рассуждений на финансовых вопросах ниже — **проверить** на eval-наборе (E2.4-T7). Цена и лимиты — **проверить**. |
| **Б. Зарубежная модель с обезличиванием** (Claude напрямую или через OpenRouter) | Лучшее качество советника. Уже интегрировано. | Агрегаты трат, привязанные к сессии пользователя, могут считаться ПДн. Тогда нужны отдельное согласие на трансграничную передачу, уведомление РКН и оценка страны. Оплата из РФ и устойчивость доступа. |
| **В. Гибрид** | Категоризация мерчантов (это не ПДн) — любой провайдер с кешем. Советник — российская модель по умолчанию, зарубежная — по явному согласию пользователя («улучшенный режим»). | Две интеграции, сложнее поддержка. |

**Рекомендация:** В.
- В E1.3 включить LLM-категоризацию только для обезличенных названий мерчантов: P2P и ФИО не отправляются, кеш глобальный.
- В E2.4 принять решение по результатам eval-прогона трёх провайдеров.
- Юристу — **проверить**:
  - являются ли агрегаты без идентификаторов обезличенными данными в смысле 152-ФЗ (с учётом изменений об обезличенных данных, вступивших в силу в 2025 году);
  - нужно ли уведомление о трансграничной передаче.

**Блокирует:** E1.3-T8 (до решения флаг выключен, цель 85% достигается хуже — около 75%), E2.4 целиком.

**Решение владельца (18.10.2026):** провайдер — **RouterAI** (routerai.ru): российский шлюз к моделям с OpenAI-совместимым API и оплатой в рублях.
- Вместо трёх адаптеров (OpenRouter, GigaChat, YandexGPT) — один OpenAI-совместимый клиент: адрес, ключ и модель задаются в `.env` (`LLM_BASE_URL`, `LLM_API_KEY`, модели — отдельно для категоризации и советника). OpenRouter убирается.
- Модель выбирается eval-прогоном (E2.4-T7) среди моделей, доступных через RouterAI: российские и зарубежные.
- По умолчанию в LLM уходят только обезличенные данные: названия мерчантов без P2P и ФИО (E1.3), агрегаты и операции без ФИО, номеров счетов, карт и телефонов (E2.4).

**Ещё открыто — 152-ФЗ.** Шлюз в РФ не отменяет трансграничную передачу, если сама модель зарубежная. До запуска LLM-функций **проверить**:
- договор и политику RouterAI: является ли он оператором или обработчиком ПДн, есть ли запись в реестре РКН, куда и кому передаются запросы для каждой модели, хранятся ли они;
- у юриста — те же вопросы об обезличенных агрегатах и уведомлении о трансграничной передаче, что выше.

До этого флаги LLM-категоризации и советника выключены на проде; разработка и eval идут на синтетических данных.

## D6. Вход через Госуслуги (ЕСИА) после 31.12.2026
**Вопрос.** До конца года реализовать реальную ГОСТ-подпись (КриптоПро, типовое решение) или временно отключить вход через ЕСИА?

**Факты из кода:**
- сейчас запрос подписывается HMAC (заглушка, `esiaService.ts`);
- пользователи, созданные через ЕСИА, имеют `passwordHash: ''` и телефон-заглушку `+7<timestamp>`, если ЕСИА не вернула мобильный;
- после отключения ЕСИА такие пользователи не смогут войти.

| Вариант | Плюсы | Минусы |
|---|---|---|
| Реализовать ГОСТ-подпись | Вход в один клик, подтверждённые данные | КриптоПро CSP (лицензия), сертификат, регистрация ИС в ЕСИА, требования с 2027 года (типовое решение или проверка СКЗИ в ФСБ — **проверить**). Несколько недель работы плюс бюрократия. Для продукта сейчас это не ключевая ценность. |
| **Отключить вход через ЕСИА** | Ноль работы и рисков | Пропадает функция, которая упоминается на сайте. |

**Рекомендация:** отключить кнопку до 15.12.2026. До отключения:
1. найти пользователей с `verification_method='esia'` или `esia_oid IS NOT NULL`;
2. разослать им письмо, если есть e-mail;
3. дать вход по коду из SMS или e-mail (модуль восстановления пароля из PR #7 уже это умеет), с установкой пароля;
4. пользователей без e-mail и с телефоном-заглушкой — посчитать; если они есть, оставить ЕСИА-вход только для них до 31.12 или связаться вручную.

Вернуться к ЕСИА на этапе 3 вместе с партнёрскими сценариями.
**Блокирует:** не блокирует этап 1, но имеет жёсткий срок.

## D8. Хранение исходных файлов выписок
**Вопрос.** Сколько хранить загруженный файл выписки? Это ПДн и банковская тайна клиента.

| Вариант | Плюсы | Минусы |
|---|---|---|
| Удалять сразу после коммита | Минимизация данных, меньше риск утечки | Нельзя повторно разобрать файл после исправления парсера, сложнее поддержка («у меня неправильно загрузилось») |
| **Хранить 30 дней зашифрованным, затем удалять** | Повторный разбор и отладка с согласия пользователя; совпадает с окном отмены импорта | Хранится 30 дней |
| Хранить бессрочно | — | Нарушает принцип минимизации 152-ФЗ |

**Рекомендация:** 30 дней, AES-256-GCM, отдельный производный ключ, доступ к файлу у поддержки — только с явного согласия пользователя в тикете. Строки `import_rows` с исходными ячейками — тоже 30 дней. Отразить в политике конфиденциальности.
**Блокирует:** E1.2-T4.
**Решение владельца (18.10.2026):** по рекомендации — 30 дней в зашифрованном виде, затем удаление; `import_rows` — тоже 30 дней.

## D9. Фоновые задачи и воркер
**Вопрос.** На чём делать очереди и где их выполнять, если у api-контейнера лимит 512 МБ?

| Вариант | Плюсы | Минусы |
|---|---|---|
| **pg-boss на существующем PostgreSQL + отдельный контейнер `fintrack-worker` из того же образа** | Без новой инфраструктуры; транзакционная постановка задач вместе с данными; cron встроен | Нагрузка на ту же БД (при наших объёмах незначительная) |
| Redis + BullMQ | Стандарт, быстрее, Redis пригодится для кешей и лимитов при нескольких экземплярах api | Новый сервис на VPS (память, бэкапы, мониторинг), обновить `vps-server-infra` |
| Задачи внутри api-процесса | Проще всего | Разбор PDF на 512 МБ может уронить API, нет изоляции |

**Рекомендация:** pg-boss и отдельный воркер. Redis — когда понадобится второй экземпляр api (rate-limit и tokenCache сейчас в памяти, это ограничение этапа 0). Перед запуском проверить свободную память VPS (`docs/Server_State.md` в `vps-server-infra`): воркеру нужно 512 МБ.
**Блокирует:** E1.0-T2 и всё асинхронное.
**Решение владельца (18.10.2026):** по рекомендации — pg-boss на существующем PostgreSQL и отдельный контейнер `fintrack-worker` из образа API.

## D11. Представление денег в коде
**Вопрос.** Drizzle отдаёт `decimal` строкой, а фронтенд сейчас делает `parseFloat`. Как считать деньги?

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Строки в API и БД (`numeric(15,2)`), расчёты в SQL; в TS — копейки в `bigint` через маленький модуль `lib/shared/money.ts`** | Нет ошибок плавающей точки, нет зависимости, агрегаты считает PostgreSQL | Аккуратность при конвертации, линтер-правило против `parseFloat` для сумм |
| `decimal.js` / `big.js` | Привычно | Зависимость, медленнее, объекты в состоянии React |
| Хранить копейки `bigint` в БД | Целочисленная арифметика | Большая миграция, неудобно в SQL-отчётах |

**Рекомендация:** первый вариант. В OpenAPI — `type: string, pattern: '^-?\d+\.\d{2}$'`.
**Блокирует:** E1.1.
**Решение владельца (18.10.2026):** по рекомендации — `numeric(15,2)` в БД, строки в API, агрегаты в SQL, копейки в `bigint` в TypeScript (`lib/shared/money.ts`).

| **Локальная сборка в GitHub Actions** (`eas build --local` или `expo prebuild` + Gradle; macOS-раннер для iOS) | Ключи у нас, нет зависимости от Expo-облака | Настройка CI, macOS-минуты платные, OTA — свой сервер `expo-updates` (статическая раздача манифестов с fin-wall.ru) |

**Рекомендация:** Android — локальная сборка в GitHub Actions с первого дня. iOS — на этапе 3: EAS, если оплата доступна, иначе macOS-раннер. OTA — собственный endpoint обновлений (протокол expo-updates открыт). Push — напрямую FCM, RuStore и APNs, без Expo Push Service.
**Блокирует:** E2.1-T1, E2.9-T1.
**Решение (23.10.2026):** владелец выбрал нативное приложение на Expo раньше PWA (E2.1 до E1.7). Сборка — по рекомендации:
Android собирается в GitHub Actions (`expo prebuild` + Gradle, `.github/workflows/mobile-android.yml`), ключ подписи — в секретах
репозитория. EAS не используется; к нему можно вернуться для iOS на этапе 3.
